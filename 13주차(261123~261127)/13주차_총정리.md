## A. LLM 에이전트 — create_agent (11/23)

지난주 Tool Calling은 ① LLM이 `tool_calls`로 호출을 결정 → ② 코드가 `도구.invoke()`로 실행하는 과정을 **손으로** 짰다. **`create_agent`는 이 "결정 → 실행 → 재판단" 루프를 스스로 도는 에이전트**를 만든다.

```python
from langchain.agents import create_agent

agent = create_agent(model=llm, tools=[add, multiply, subtract, divide],
                     system_prompt="계산이 필요하면 도구를 사용하세요.")
result = agent.invoke({"messages": [{"role":"user", "content":"33과 7을 곱한 후 4를 더해줘"}]})
print(result["messages"][-1].content)   # 최종 답변
```

- **`create_agent(model, tools, system_prompt)`**: LLM·도구·행동지침을 묶어 에이전트를 만든다. 내부적으로 8주차에 손으로 짜던 LangGraph(LLM↔도구 순환) 구조가 자동 생성된다.
- **`result["messages"]`**: 에이전트가 거친 **모든 단계**가 쌓인다 — HumanMessage(질문) → AIMessage(도구 호출 결정, `tool_calls`) → ToolMessage(실행 결과) → 최종 AIMessage(종합 답변). `isinstance(msg, AIMessage) and msg.tool_calls`로 어떤 도구를 어떤 인자로 불렀는지 추적한다.
- **다단계 연쇄**: "65−35 후 ×3 후 +10" 같은 질문은 앞 결과를 다음 계산에 넘겨 **도구를 순서대로 여러 번** 호출한다. **`config={"recursion_limit":20}`** 으로 반복 상한을 둬 무한 반복을 막는다.
- **오류 대비 2겹**: `system_prompt`에 "실패하면 오류를 설명하라"는 지침 + `try/except`(구체 예외 먼저, `Exception` 나중). 여기에 역할을 구체화한 프롬프트·함수화·`while input()` 루프를 더하면 **대화형 계산 에이전트**가 된다.

## B. 머신러닝 모델링 실전

### B-1. 앙상블 3종 — Bagging·Voting·Stacking (11/24)

**앙상블은 여러 모델을 합쳐 하나보다 나은 성능을 내는** 기법이다. 대표 방식 세 가지를 cancer(분류)·california·diabetes(회귀)로 실습했다.

- **Bagging(배깅)**: **같은 모델**을 데이터 무작위 복원추출(`bootstrap`, `max_samples`)로 여러 개 학습해 평균/투표. 과적합·분산을 줄인다(RandomForest가 대표).
  ```python
  BaggingRegressor(DecisionTreeRegressor(), n_estimators=10, max_samples=0.8)
  ```
- **Voting(보팅)**: **서로 다른 모델들**(XGB·LightGBM·RandomForest·CatBoost)을 묶어 투표. **`voting='hard'`**(다수결)·**`'soft'`**(확률 평균, 보통 더 나음), 회귀는 평균.
  ```python
  VotingClassifier(estimators=[('XGB',xgb),('RF',rf),('CAT',cat),('LG',lg)], voting='soft')
  ```
- **Stacking(스태킹)**: 1차 모델들의 **예측을 새 특성으로 만들어 메타 모델이 최종 판단**하는 2층 구조. 수동 구현(`np.array(예측들).T`)은 **데이터 누수** 위험이 있어, **`StackingClassifier(..., cv=5)`** 의 교차검증으로 안전하게 자동화한다.
- 이번에 **LightGBM·CatBoost**가 XGBoost와 함께 "그래디언트 부스팅 3대장"으로 등장했다.

| 기법 | 모델 구성 | 합치는 방법 |
|---|---|---|
| **Bagging** | 같은 모델 여러 개 + 데이터 샘플링 | 평균/다수결 |
| **Voting** | 서로 다른 모델들 | 투표(hard)/확률평균(soft) |
| **Stacking** | 1차 여러 + 2차 메타 | 메타 모델이 최종 결정 |

### B-2. 모델 저장·불러오기 · 조기 종료 · 상관계수 (11/25)

**학습한 모델을 파일로 저장해 두고, 재학습 없이 불러 쓰는** 세 가지 방법.

| 방식 | 저장 | 불러오기 | 특징 |
|---|---|---|---|
| **joblib** | `joblib.dump(model, 경로)` | `joblib.load(경로)` | 대용량 배열(ML 모델)에 효율적 |
| **pickle** | `pickle.dump(model, open(경로,'wb'))` | `pickle.load(open(경로,'rb'))` | 파이썬 범용 객체 직렬화 |
| **xgboost** | `model.save_model('*.json')` | 빈 모델 뒤 `model.load_model(...)` | XGB 자체 포맷, 버전·환경 호환 |

- 셋 다 목적은 같다("학습한 모델을 보관 → 재학습 없이 복원"). 저장과 로드의 **경로·확장자는 정확히 일치**시켜야 한다. 모델뿐 아니라 **DataFrame 같은 데이터도** 저장할 수 있다.
- **조기 종료(early stopping)**: 공통으로 쓴 XGB 학습에서 `set_params(**파라미터)`로 하이퍼파라미터를 한 번에 적용하고, **`early_stopping_rounds=20` + `eval_set=[(x_test,y_test)]`** 로 검증 점수가 개선되지 않으면 자동으로 멈춘다(`n_estimators`를 크게 잡아도 과적합·낭비 방지).
- **상관계수(correlation)**: 두 변수가 함께 변하는 정도를 −1~1로 나타낸 값(+1 양의 상관, −1 음의 상관, 0 무상관). **`df.corr()`** 로 상관관계 행렬을 구하고 **`seaborn.heatmap`**(`annot`·`square`·`cbar`)으로 시각화한다. 선형 관계의 세기·방향만 나타내며 **인과를 뜻하지는 않는다.**

## 한 주 핵심 한 줄

> **LLM 에이전트**는 `create_agent(model, tools, system_prompt)`로 지난주 수동 Tool Calling을 자동 반복 루프로 묶은 것으로, `result["messages"]`에 쌓인 대화 흐름(Human·도구호출 AIMessage·ToolMessage·최종 AIMessage)으로 다단계 작업을 수행하며 `recursion_limit`으로 반복을 제한하고 프롬프트 지침+`try/except`로 오류를 다룬다. **머신러닝 실전**에서는 앙상블 3종 — **Bagging**(같은 모델+데이터 샘플링)·**Voting**(다른 모델들의 hard/soft 투표)·**Stacking**(예측을 메타 모델에 재입력, `cv`로 누수 방지)과 LightGBM·CatBoost를 익히고, 학습한 모델을 **joblib·pickle·xgboost(save_model)** 로 저장·복원하며 **`early_stopping_rounds`+`eval_set`** 으로 조기 종료하고, **`df.corr()`+히트맵**으로 변수 간 상관관계(−1~1, 인과 아님)를 분석했다.
