## 1. keras69_ensemble4.py — 입력 1개를 출력 2개로 분기

keras69의 앙상블은 네 가지 형태로 나뉜다.

| 파일 | 입력 | 출력 | 구조 |
|------|------|------|------|
| ensemble1 | 2개 | 1개 | 입력 2개 → Concatenate → 출력 1 |
| ensemble2 | 3개 | 1개 | 입력 3개 → Concatenate → 출력 1 |
| ensemble3 | 3개 | 2개 | 입력 3개 → Concatenate → **분기 2개 출력** |
| ensemble4 | **1개** | **2개** | 입력 1개 → 공통 몸통 → **분기 2개 출력** |

ensemble4는 입력이 하나인데 출력이 둘이다. 입력부터 공통된 층(몸통)을 거친 뒤, 그 지점에서 두 갈래로 갈라져 각각 다른 출력을 낸다.

```python
#2-1. 공통 몸통 (입력 1개)
input1 = Input(shape=(2,))
dense1 = Dense(10, activation='relu', name='han1')(input1)
dense2 = Dense(20, activation='relu', name='han2')(dense1)
dense3 = Dense(30, activation='relu', name='han3')(dense2)
output1 = Dense(5, activation='relu', name='han4')(dense3)   # 여기까지 공통, 아래서 갈라짐

#2-2. 분기1 (y1용)
b1 = Dense(10, activation='relu', name='b1_1')(output1)
b1 = Dense(10, activation='relu', name='b1_2')(b1)
last_output1 = Dense(1, name='last1')(b1)

#2-3. 분기2 (y2용)
b2 = Dense(10, activation='relu', name='b2_1')(output1)
b2 = Dense(10, activation='relu', name='b2_2')(b2)
last_output2 = Dense(1, name='last2')(b2)

#2-4. 모델 정의 — 입력 1개, 출력 2개
model = Model(inputs=input1, outputs=[last_output1, last_output2])
```

**함수형 API에서 분기가 만들어지는 원리.** 함수형 API는 `층(이전층)` 형태로 층을 연결한다. `output1`이라는 같은 텐서를 `b1`과 `b2` 두 층에 각각 입력으로 넘기면, 그래프가 그 지점에서 둘로 갈라진다. `output1`까지는 한 번만 계산되어 두 분기가 공유하고, 그 뒤부터 각자 독립적으로 학습된다.

**출력이 2개일 때 fit / predict 규칙.**

```python
#3. 훈련 — y를 리스트로 묶어서 넘긴다
model.fit(x_train, [y1_train, y2_train], epochs=150, batch_size=8)

#4. 예측 — 출력이 2개이므로 두 변수로 언패킹해서 받는다
y1_predict, y2_predict = model.predict(x_test)
```

출력이 여러 개면 타깃도 `[y1, y2]` 리스트로 넘겨야 한다. 리스트로 묶지 않고 `y1_train, y2_train`을 각각 인자로 넘기면 두 번째가 `batch_size`로 잘못 들어가 "multiple values for batch_size" 에러가 난다. 예측값도 출력 수만큼 반환되므로 `y1_predict, y2_predict = ...`로 언패킹한다. 한 변수로 받으면 리스트가 통째로 들어가 인덱싱이 꼬인다.

`model.evaluate`의 반환값도 `[전체 loss, 출력1 loss, 출력2 loss]` 형태가 된다.

## 2. keras70_stock — 아모레·하이닉스 앙상블로 삼성전자 시가 예측

### 2-0. 과제 정의

- **목표:** 내일(261013) 삼성전자 **시가** 예측
- **필수 조건:** ① 앙상블 ② LSTM·Conv1D 둘 다 사용(시계열) ③ 입력 컬럼 종목당 5개 이상 ④ 가중치(weight) 저장·제출
- **로직:** 아모레 + 하이닉스를 앙상블해 삼성전자 시가를 출력. 입력 종목은 더 추가해도 되지만 **시가는 입력으로 쓰지 않는다 — 시가가 바로 예측 대상 y이기 때문이다.**
- **제출물:** ① predict 코드 ② 원코드 ③ weight 파일

### 2-1. 원코드 (keras70_1_stock.py)

```python
import numpy as np
import pandas as pd
from sklearn.model_selection import train_test_split
from sklearn.preprocessing import MinMaxScaler
from sklearn.metrics import r2_score, mean_squared_error
from tensorflow.keras.models import Model
from tensorflow.keras.layers import Input, Dense, LSTM, Conv1D, Flatten, Concatenate
from tensorflow.keras.callbacks import EarlyStopping

#1. 데이터
USE_COLS  = ['고가', '저가', '종가', '거래량', '금액(백만)', '기관', '외인(수량)']  # ★시가 제외(=y)
TIMESTEPS = 10

PATH = 'C:/study/_data/stock/'
F_AMORE = PATH + '아모레261012.csv'
F_HYNIX = PATH + '하이닉스261012.csv'
F_SAM   = PATH + '삼성전자261012.csv'
WEIGHT_PATH = 'C:/study/_save/keras70/keras70_이민수.weights.h5'

def load_csv(path):
    df = pd.read_csv(path, encoding='cp949', thousands=',', index_col=0)
    df.index = pd.to_datetime(df.index)
    return df.sort_index()
```

**CSV를 읽을 때 지정하는 세 가지.** 증권사에서 받은 주가 CSV는 그대로 읽으면 깨지거나 문자열이 된다.

- `encoding='cp949'` — 컬럼명이 한글(일자, 시가, 고가 …)이다. 기본 UTF-8로 읽으면 깨진다. cp949(euc-kr 계열)로 읽어야 한다.
- `thousands=','` — 값이 `"1,640,000"`처럼 천 단위 콤마가 있는 **문자열**이다. 이 옵션을 줘야 콤마를 떼고 숫자 1640000으로 읽는다. 없으면 문자열이라 연산·스케일링이 안 된다.
- `index_col=0` — 0번 컬럼(일자)을 인덱스로 삼는다. 뒤에 날짜 기준으로 종목을 합칠 때 쓴다.

**`sort_index()`로 날짜를 오름차순으로 뒤집는다.** 원본 CSV는 최신 날짜가 맨 위(내림차순)다. 시계열은 과거 → 현재 순서여야 "과거 10일을 보고 다음날을 예측"하는 윈도우가 성립하므로, 인덱스(날짜) 기준 오름차순으로 정렬한다.

```python
amore = load_csv(F_AMORE)
hynix = load_csv(F_HYNIX)
sam   = load_csv(F_SAM)

# 종목마다 거래일이 달라서 날짜 교집합(inner join)으로 맞춘다
am = amore[USE_COLS].add_prefix('am_')
hy = hynix[USE_COLS].add_prefix('hy_')
sy = sam[['시가']].rename(columns={'시가': 'sam_open'})
merged = am.join(hy, how='inner').join(sy, how='inner').dropna()

x1 = merged[[c for c in merged.columns if c.startswith('am_')]].values   # (전체, 7)
x2 = merged[[c for c in merged.columns if c.startswith('hy_')]].values   # (전체, 7)
y  = merged['sam_open'].values                                           # (전체,)
N_FEAT = x1.shape[1]
```

**`add_prefix`로 컬럼 이름 충돌을 막는다.** 세 종목 모두 '고가', '저가' …로 컬럼명이 같다. 그대로 합치면 어느 종목 것인지 구분이 안 되므로, 아모레는 `am_`, 하이닉스는 `hy_`를 앞에 붙여 `am_고가`, `hy_고가`처럼 구분한다. 삼성은 시가 한 컬럼만 `sam_open`으로 이름을 바꿔 쓴다(y로 쓸 값).

**`join(how='inner')` — 날짜 교집합으로만 맞춘다.** 종목마다 상장일·거래 정지일이 달라 날짜 줄 수가 다르다. 세 종목이 **모두 거래된 날짜**에만 행이 남도록 inner join으로 교집합을 잡는다. 날짜가 어긋난 채로 합치면 아모레의 어느 날과 삼성의 다른 날이 한 행에 섞인다. `dropna()`로 빈 값이 있는 행도 제거한다.

**입력 컬럼 7개에 시가가 없다.** `USE_COLS`는 고가·저가·종가·거래량·금액·기관·외인 7개다. 시가는 빠져 있다. 예측 대상 y가 삼성 시가이므로, 입력(x)에 시가를 넣으면 정답을 미리 알려주는 셈이라 제외한다.

```python
#1-2. 시계열 윈도우 자르기 — 10일치[i:i+10]를 보고 → 그 다음날 삼성 시가가 정답
X1, X2, Y = [], [], []
for i in range(len(merged) - TIMESTEPS):
    X1.append(x1[i : i + TIMESTEPS])
    X2.append(x2[i : i + TIMESTEPS])
    Y.append(y[i + TIMESTEPS])
X1, X2, Y = np.array(X1), np.array(X2), np.array(Y)
# X1:(N,10,7) X2:(N,10,7) Y:(N,)

# 내일(10/13) 예측용 : 가장 최근 10일 윈도우
x1_pred = x1[-TIMESTEPS:].reshape(1, TIMESTEPS, N_FEAT)
x2_pred = x2[-TIMESTEPS:].reshape(1, TIMESTEPS, N_FEAT)
```

**윈도우로 입력과 정답의 시점을 어긋나게 짝짓는다.** `x1[i : i+10]`은 i일부터 10일간의 데이터이고, 그에 대한 정답 `y[i+10]`은 그 **다음날**의 삼성 시가다. 즉 "10일을 입력하면 11일째 시가를 맞춘다"는 관계를 N개 샘플로 만든다. 입력 한 샘플의 모양은 `(10, 7)` = (10일, 컬럼 7개)이고, 전체는 `(N, 10, 7)`인 3차원이다. LSTM·Conv1D 같은 시계열 층은 이 `(samples, timesteps, features)` 3차원을 입력으로 받는다.

`x1_pred`는 가장 최근 10일(마지막 행이 10/12)로 만든 한 개짜리 윈도우다. 이걸 넣으면 그 다음날인 10/13 시가가 나온다. 이 행은 어떤 윈도우의 정답으로도 쓰이지 않았으므로(미래가 없음) 오직 예측용이다.

```python
#1-3. 스케일링 (x만) — 스케일러는 원본 전체 데이터(x1, x2)로 fit
scaler1 = MinMaxScaler()
scaler2 = MinMaxScaler()
scaler1.fit(x1)
scaler2.fit(x2)
X1 = scaler1.transform(X1.reshape(-1, N_FEAT)).reshape(-1, TIMESTEPS, N_FEAT)
X2 = scaler2.transform(X2.reshape(-1, N_FEAT)).reshape(-1, TIMESTEPS, N_FEAT)
x1_pred = scaler1.transform(x1_pred.reshape(-1, N_FEAT)).reshape(1, TIMESTEPS, N_FEAT)
x2_pred = scaler2.transform(x2_pred.reshape(-1, N_FEAT)).reshape(1, TIMESTEPS, N_FEAT)
```

**스케일러는 2차원만 받는다.** `MinMaxScaler`는 `(행, 열)` 2차원만 처리한다. 윈도우 `X1`은 `(N, 10, 7)` 3차원이므로, `reshape(-1, 7)`로 `(N*10, 7)` 2차원으로 폈다가 변환 후 `reshape(-1, 10, 7)`로 되돌린다. 컬럼(feature) 수 7은 그대로 두고 앞 차원만 접었다 펴는 것이다.

**종목마다 스케일러를 따로 둔다.** 아모레와 하이닉스는 가격대·거래량 규모가 다르므로 `scaler1`, `scaler2`로 분리해 각자의 min/max로 0~1 변환한다.

**`fit`은 원본 2차원 `x1`으로 한다.** 윈도우로 자른 `X1`이 아니라 자르기 전 원본 `x1`으로 fit한다. 윈도우는 마지막 행(10/12)을 입력으로는 쓰지 않고 정답으로만 쓰기 때문에, `X1`으로 fit하면 그 날 데이터가 min/max 계산에서 빠진다. predict 코드는 원본으로 fit하므로, 양쪽 기준을 똑같이 맞추려면 원코드도 원본 `x1`으로 fit해야 한다. (y(시가)는 스케일링하지 않았다. 출력값을 그대로 원(₩) 단위로 받는다.)

```python
#1-4. 훈련/테스트 분리 (shuffle=True)
x1_train, x1_test, x2_train, x2_test, y_train, y_test = train_test_split(
    X1, X2, Y, train_size=0.8, random_state=4096, shuffle=True,
)
```

입력이 2개(x1, x2)이므로 train/test 분리도 두 입력과 y를 함께 넘겨 같은 기준으로 나눈다. `shuffle=True`는 keras69 방식 그대로다. 이 종목은 과거에서 최근으로 가격이 크게 오르는 추세라, 시간 순서대로 자르면 테스트 구간(최근 고가)이 학습 구간(과거 저가)에서 본 적 없는 가격대가 되어 예측이 무너진다. 섞어서 전 구간을 고루 학습시키면 그 문제를 피한다. (추측: 다만 미래 샘플이 학습에 섞이므로 R² 등 평가지표는 실제 예측력보다 높게 나온다.)

```python
#2. 모델 (앙상블)
# 2-1. 아모레 가지 → LSTM
input1 = Input(shape=(TIMESTEPS, N_FEAT))
lstm1 = LSTM(64, activation='relu')(input1)
dense1 = Dense(32, activation='relu')(lstm1)
output1 = Dense(16, activation='relu')(dense1)

# 2-2. 하이닉스 가지 → Conv1D
input2 = Input(shape=(TIMESTEPS, N_FEAT))
conv1 = Conv1D(64, 2, activation='relu')(input2)
conv2 = Conv1D(32, 2, activation='relu')(conv1)
flat = Flatten()(conv2)
output2 = Dense(16, activation='relu')(flat)

# 2-3. 합치기 → 삼성 시가 1개 출력
merge = Concatenate()([output1, output2])
m1 = Dense(32, activation='relu')(merge)
m2 = Dense(16, activation='relu')(m1)
last_output = Dense(1)(m2)

model = Model(inputs=[input1, input2], outputs=last_output)
```

**두 입력에 서로 다른 시계열 층을 쓴다(과제 조건).** 아모레 가지는 LSTM, 하이닉스 가지는 Conv1D로 각각 특징을 뽑은 뒤 `Concatenate`로 두 가지의 결과를 이어붙여 하나로 합치고, Dense를 거쳐 삼성 시가 한 값을 출력한다. LSTM과 Conv1D 모두 입력은 같은 `(timesteps, features)` 3차원이다.

- **LSTM**은 시간 순서를 따라가며 상태를 기억하는 순환 층이다. 기본 출력은 마지막 시점의 결과 하나(2차원)라 바로 Dense로 넘어간다.
- **Conv1D**는 시간 축을 따라 `kernel_size`(여기선 2)만큼의 구간을 훑으며 지역적 패턴을 뽑는 합성곱 층이다. 출력이 아직 `(timesteps, filters)` 3차원이므로, Dense로 넘기기 전에 `Flatten()`으로 1줄(2차원)로 펴야 한다.

**마지막 `Dense(1)`에는 활성화 함수가 없다.** 시가(가격)는 연속적인 실수값을 예측하는 회귀 문제다. 회귀의 출력층은 값의 범위를 제한하지 않도록 활성화 함수를 두지 않는다(선형 출력). (relu를 두면 음수가 막히고, sigmoid를 두면 0~1로 눌려 가격을 못 낸다.)

```python
#3. 컴파일, 훈련
es = EarlyStopping(monitor='val_loss', mode='min', patience=50, restore_best_weights=True)
model.compile(loss='mse', optimizer='adam')
model.fit([x1_train, x2_train], y_train,
          epochs=1000, batch_size=16, validation_split=0.2, callbacks=[es])

model.save_weights(WEIGHT_PATH)   # ★ 가중치 저장
```

**입력이 2개이므로 fit에도 `[x1_train, x2_train]` 리스트로 넘긴다.** 모델의 `inputs=[input1, input2]` 순서와 리스트 순서가 일치해야 한다.

**회귀의 손실은 mse.** 예측값과 실제값 차이의 제곱 평균이다. 분류의 crossentropy 대신 회귀에서 쓴다.

**EarlyStopping.** `val_loss`(검증 손실)가 50 에폭(patience) 동안 더 나아지지 않으면 학습을 멈춘다. `restore_best_weights=True`는 멈출 때 마지막 상태가 아니라 **가장 좋았던 시점의 가중치로 되돌린다.** 그래서 이 뒤에 `save_weights`로 저장하면 best 상태가 저장된다.

**`save_weights` — 가중치만 저장한다(제출 조건).** 모델이 학습한 숫자(가중치)만 파일로 남긴다. 모델 구조나 스케일 규칙은 이 파일에 들어가지 않는다. 이 점이 predict 코드 구성을 결정한다(아래).

```python
#4. 평가, 예측
loss = model.evaluate([x1_test, x2_test], y_test)
y_predict = model.predict([x1_test, x2_test])
r2 = r2_score(y_test, y_predict)
rmse = np.sqrt(mean_squared_error(y_test, y_predict))

tomorrow = model.predict([x1_pred, x2_pred])
print('내일(2026-10-13) 삼성전자 시가 예측:', int(tomorrow[0][0]), '원')
```

**회귀 평가지표.** 정확도(accuracy)는 분류용이라 회귀에는 쓰지 않는다. 대신 R²(1에 가까울수록 좋음)와 RMSE(mse에 루트를 씌워 원래 단위 ₩로 되돌린 오차)를 본다.

### 2-2. predict 코드 (keras70_2_stock_predict.py)

predict 코드는 **학습 없이 weight만 불러와 내일 시가 한 값만 출력**한다. 그런데 weight 파일에는 학습된 숫자만 들어 있고 모델 구조도 스케일 규칙도 없다. 그래서 두 가지를 다시 만들어줘야 한다.

```python
#2. 모델 (원코드와 똑같은 구조)
input1 = Input(shape=(TIMESTEPS, N_FEAT))
lstm1 = LSTM(64, activation='relu')(input1)
...
last_output = Dense(1)(m2)
model = Model(inputs=[input1, input2], outputs=last_output)
model.load_weights(WEIGHT_PATH)   # ★ 학습된 weight 불러오기
```

**① 모델 구조 재정의.** `load_weights`는 비어 있는 모델 틀에 저장된 숫자를 자리마다 부어 넣는 방식이다. 숫자를 받을 틀(층 구조)이 먼저 있어야 한다. 그래서 원코드와 **글자 하나까지 똑같은 구조**를 세운 뒤 `load_weights`로 가중치를 얹는다. 구조가 다르면 자리가 안 맞아 에러가 난다.

```python
#1-2. 스케일링 (원코드와 동일: 원본 전체로 fit)
scaler1 = MinMaxScaler(); scaler1.fit(x1)
scaler2 = MinMaxScaler(); scaler2.fit(x2)
x1_pred = scaler1.transform(x1[-TIMESTEPS:]).reshape(1, TIMESTEPS, N_FEAT)
x2_pred = scaler2.transform(x2[-TIMESTEPS:]).reshape(1, TIMESTEPS, N_FEAT)
```

**② 스케일러 재계산.** 입력을 0~1로 바꾼 변환 규칙(각 컬럼의 min/max)도 weight에는 없다. 예측 입력도 학습 때와 똑같은 기준으로 변환해야 결과가 맞으므로, CSV를 다시 읽어 원코드와 동일하게 스케일러를 fit한다. 원본 전체로 fit하는 기준, 세 종목 inner join으로 날짜를 맞추는 절차까지 원코드와 같아야 min/max가 완전히 일치한다. (predict에서 삼성 CSV를 읽는 이유는 시가 값을 쓰려는 게 아니라, 원코드와 똑같은 날짜 교집합을 만들기 위해서다.)

**실제 "예측"은 맨 끝 세 줄이다.** 윈도우 스케일 → `model.predict` → 출력. 앞의 로드·구조·스케일러는 모두 이 세 줄을 돌리기 위한 준비다. predict에는 evaluate(평가)가 없다. 평가는 정답이 있어야 하는데 내일 시가는 아직 정답이 없기 때문이다. 평가는 원코드의 test셋에서 하고, predict는 메일 제목에 쓸 예측값 하나만 뽑는다.

**weight만 저장할 때 생기는 제약.** 만약 전체 모델(`.keras`)을 저장할 수 있었다면 `load_model` 한 줄로 구조까지 복원돼 ①이 사라진다. 스케일러를 파일(`.pkl`)로 저장할 수 있었다면 불러오기만 하면 돼 ②가 사라진다. "weight만 제출" 조건 때문에 구조 재정의와 스케일러 재계산이 생긴 것이다.

## 3. rag21_Gradio_history.py — 대화 기록을 기억하는 RAG 챗봇

이전 RAG 실습(FAISS 벡터DB 적재·검색, 임베딩, 모델 연결)에 **대화 기록(history)** 을 더해, 앞서 나눈 대화를 기억하는 챗봇을 Gradio로 띄운다. 데이터 적재·FAISS 저장/로드·임베딩 부분은 이전과 같고, 달라진 핵심은 프롬프트에 대화 기록 자리를 넣고 Gradio로 연결하는 부분이다.

```python
from langchain_core.prompts import ChatPromptTemplate, MessagesPlaceholder
from langchain_core.messages import HumanMessage, AIMessage

prompt = ChatPromptTemplate.from_messages([
    ("system", """
    다음 컨텍스트를 바탕으로 질문에 답변해 주세요.
    컨텍스트 관련 정보가 없다면, "주어진 정보로는 답변할 수 없습니다"
    라고 말해주세요.
    컨텍스트 : {context}
    """),
    MessagesPlaceholder(variable_name="chat_history"),
    ("human", "{input}")
])
```

**`MessagesPlaceholder` — 프롬프트 안에 대화 기록이 들어갈 빈 자리를 만든다.** system 지시와 이번 human 질문(`{input}`) 사이에, 지난 대화 메시지들이 통째로 들어갈 자리를 `chat_history`라는 이름으로 비워 둔다. 실행할 때 이 이름으로 메시지 리스트를 넘기면 그 자리에 채워진다. 이렇게 이전 대화가 매 질문마다 프롬프트에 함께 들어가므로 모델이 맥락을 이어갈 수 있다.

```python
docu_chain = create_stuff_documents_chain(model, prompt)    # 프롬프트 + 모델 연결
rag_chain = create_retrieval_chain(retriever, docu_chain)   # 검색기 + 위 체인 연결
```

**RAG 체인 두 단계.** `create_stuff_documents_chain`은 검색된 문서들을 프롬프트의 `{context}`에 밀어넣어(stuff) 모델에 전달하는 체인이다. `create_retrieval_chain`은 그 앞에 검색기(retriever)를 붙여 "질문으로 문서 검색 → 검색 결과를 context로 넣어 답변 생성"으로 이어지는 전체 RAG 흐름을 만든다.

```python
import gradio as gr

def answer_invoke(message, history):
    chat_history = []
    for item in history:
        content = item["content"]
        if item["role"] == "user":
            chat_history.append(HumanMessage(content=content))
        elif item["role"] == "assistant":
            chat_history.append(AIMessage(content=content))

    response = rag_chain.invoke({
        "input" : message,
        "chat_history" : chat_history
    })
    return response["answer"]

demo = gr.ChatInterface(fn=answer_invoke, title='Test Chat Bot')
demo.launch()
```

**`gr.ChatInterface` — 채팅 UI를 자동으로 만들어 주는 Gradio 컴포넌트.** 답변 함수 하나만 넘기면 입력창·대화창이 있는 챗봇 화면을 띄운다. `demo.launch()`가 로컬 웹서버를 열어 브라우저에서 대화할 수 있게 한다.

**답변 함수의 두 인자 `(message, history)`.** `ChatInterface`는 사용자가 입력할 때마다 이 함수를 부르면서 **이번 입력(`message`)** 과 **지금까지의 대화(`history`)** 를 자동으로 넘긴다. `history`는 `{"role": "user"/"assistant", "content": "..."}` 형태의 딕셔너리 리스트다.

**Gradio의 history를 LangChain 메시지로 변환한다.** Gradio가 주는 history는 딕셔너리 형태이고, LangChain 프롬프트의 `chat_history` 자리는 `HumanMessage` / `AIMessage` 객체 리스트를 받는다. 형식이 다르므로, history를 돌면서 role이 user면 `HumanMessage`, assistant면 `AIMessage`로 바꿔 담은 뒤 `invoke`에 `chat_history`로 넘긴다. 이 변환이 "이전 대화 기억"을 실제로 연결하는 부분이다.

`rag_chain.invoke`에 `input`(이번 질문)과 `chat_history`(지난 대화)를 함께 넘기면, 검색된 문서 context와 지난 대화가 모두 담긴 프롬프트로 답변이 생성되고, `response["answer"]`에서 최종 답변 문자열을 꺼내 반환한다.
