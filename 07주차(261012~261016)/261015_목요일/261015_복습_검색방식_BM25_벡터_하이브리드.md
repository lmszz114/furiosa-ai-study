# 261015 복습 — 검색 방식 3가지: BM25(키워드) · 벡터(의미) · 하이브리드

> RAG의 "검색(R)" 단계를 세 방식으로 다룬다. **BM25**는 단어가 겹치는지(키워드)로 찾고, **벡터 검색**은 뜻이 비슷한지(의미)로 찾는다. **하이브리드**는 둘을 결합해 키워드와 의미를 모두 활용한다.

## 목차
1. rag23_01 — BM25 검색 (키워드 기반)
2. rag23_02 — 벡터 검색 (의미 기반)
3. rag23_03 — 하이브리드 검색 (BM25 + 벡터 결합)

---

## 1. rag23_01 — BM25 검색 (키워드 기반)

```python
from langchain_core.documents import Document

texts = [
    Document(page_content="삼성전자는 반도체를 생산하는 기업이다."),
    Document(page_content="삼성전자는 갤럭시 스마트폰을 판매한다."),
    Document(page_content="SK하이닉스는 메모리 반도체를 생산한다."),
    Document(page_content="엔비디아는 인공지능 연산용 GPU를 설계한다."),
    Document(page_content="애플은 아이폰을 개발하는 기업이다."),
    Document(page_content="테슬라는 전기자동차를 제조한다."),
    Document(page_content="삼성전자는 AI 반도체 기술을 연구한다."),
    Document(page_content="반도체는 컴퓨터의 핵심 부품이다."),
]
query = "삼성전자의 반도체 사업"

from langchain_community.retrievers import BM25Retriever
bm25_retriever = BM25Retriever.from_documents(texts)
bm25_retriever.k = 3                       # 가져올 문서 수
bm25_docs = bm25_retriever.invoke(query)   # 질문과 단어가 겹치는 문서 검색

for doc in bm25_docs:
    print(doc.page_content)
```

**`Document(page_content=...)`로 문서를 코드에서 직접 만든다.** 지금까지는 txt·PDF를 파일에서 불러왔지만, 여기서는 검색 방식 비교가 목적이라 짧은 문장 8개를 `Document` 객체로 손수 만들어 쓴다. `page_content`가 문서 본문이다.

**BM25는 키워드(단어) 기반 검색이다.** 이름은 Best Match 25에서 왔다. 질문과 문서에 **같은 단어가 얼마나 겹치는지**로 점수를 매겨 높은 순으로 가져온다. "삼성전자", "반도체" 같은 단어가 들어간 문장이 상위로 올라온다. 의미·동의어는 따지지 않고 단어 표면의 일치를 본다. 그래서 임베딩(벡터화)이 필요 없어 빠르고, 정확히 그 단어가 있는 문서를 잘 찾는다. 반대로 단어가 다르면(동의어·다른 표현) 의미가 같아도 못 찾는다.

- **`BM25Retriever.from_documents(texts)`** : 문서 리스트로 BM25 검색기를 만든다.
- **`.k = 3`** : 가져올 문서 개수. `invoke(query)`로 검색을 실행한다.

## 2. rag23_02 — 벡터 검색 (의미 기반)

벡터 검색은 앞서 배운 RAG 검색 그대로다. 문서와 질문을 **임베딩(벡터)으로 바꿔, 벡터가 가까운(의미가 비슷한) 문서**를 찾는다.

```python
### 01~03. PDF 불러오기 → 청킹 → 임베딩(bge-m3)
pdf_docs = PyPDFLoader(path + "Attention_is_all_you_need.pdf").load()   # 15페이지
split_pdf_docs = Text_splitter.split_documents(pdf_docs)                # 205 청크
embeddings = HuggingFaceEmbeddings(model_name="BAAI/bge-m3", model_kwargs={"device": "cpu"})

### DB SAVE — FAISS로 저장
db = FAISS.from_documents(documents=split_pdf_docs, embedding=embeddings)
DB_PATH = './_db/Faiss23/'
db.save_local(folder_path=DB_PATH, index_name='faiss_index23')

### DB LOAD — 저장한 DB 불러오기
vector_store = FAISS.load_local(
    folder_path=DB_PATH, index_name="faiss_index23",
    embeddings=embeddings, allow_dangerous_deserialization=True)

vector_retriever = vector_store.as_retriever(search_kwargs={"k": 3})
vector_docs = vector_retriever.invoke(query)
```

**벡터 검색은 의미 기반이다.** 임베딩은 뜻이 비슷한 텍스트를 가까운 벡터로 만들므로, 질문과 **단어가 달라도 의미가 통하면** 찾아낸다. BM25가 못 잡는 동의어·다른 표현에 강하다. 대신 문서를 미리 임베딩해 VectorDB(FAISS)에 저장해두는 준비가 필요하다.

**저장(`save_local`)과 불러오기(`load_local`)의 `index_name`은 반드시 같아야 한다.** 저장 때 `index_name='faiss_index23'`으로 만든 파일을 불러올 때도 `index_name="faiss_index23"`으로 열어야 한다. 이름이 다르면 그 이름의 `.faiss` 파일이 없어 `No such file or directory` 에러가 난다. (앞 버전에서 저장은 `faiss_index19`, 불러오기는 `faiss_index23`으로 엇갈려 났던 에러를 이 이름 통일로 바로잡았다.)

- **벡터 검색의 흐름**은 이전과 동일하다: 불러오기 → 청킹 → 임베딩 → FAISS 저장/불러오기 → `as_retriever`로 검색기화 → `invoke(query)`.
- 저장은 한 번만 하고 이후엔 불러와 쓰는 것이 원칙이지만, 이 실습 파일은 비교·확인을 위해 저장과 불러오기를 함께 둔 형태다.

## 3. rag23_03 — 하이브리드 검색 (BM25 + 벡터 결합)

**하이브리드 검색은 BM25(키워드)와 벡터(의미)를 함께 써서 두 방식의 장점을 합친다.** 키워드가 정확히 겹치는 문서(BM25)와 의미가 비슷한 문서(벡터)를 모두 가져와 순위를 합친다.

```python
# BM25 검색기 (texts 기반)
bm25_retriever = BM25Retriever.from_documents(texts)
bm25_retriever.k = 3

# 벡터 검색기 (FAISS 기반)
vector_retriever = vector_store.as_retriever(search_kwargs={"k": 3})

# 하이브리드 — 두 검색기를 앙상블
from langchain_classic.retrievers import EnsembleRetriever
hybrid_retriever = EnsembleRetriever(
    retrievers=[bm25_retriever, vector_retriever],
    weights=[0.5, 0.5]       # 두 검색기의 반영 비율 (합 1)
)

hybrid_docs = hybrid_retriever.invoke(query)
for doc in hybrid_docs:
    print(doc.page_content)
```

**`EnsembleRetriever`가 여러 검색기를 하나로 묶는다.** `retrievers`에 BM25·벡터 검색기를 리스트로 넣고, `weights`로 각 검색기의 반영 비율을 준다. `[0.5, 0.5]`면 둘을 동등하게 반영한다. 각 검색기가 매긴 순위를 가중치로 합산해 최종 순위를 낸다. 키워드로도 잡고 의미로도 잡으니, 한쪽만 쓸 때 놓치는 문서를 서로 보완한다.

- **weights로 비중을 조절**한다. 키워드 정확도가 중요하면 BM25 쪽을, 의미·동의어 대응이 중요하면 벡터 쪽을 높인다.
- 이 파일에서 BM25 검색기는 직접 만든 `texts`(8문장)를, 벡터 검색기는 PDF(205청크)를 대상으로 한다. 두 검색기가 서로 다른 문서 집합을 보고 있어, 하이브리드 결과에는 두 출처의 문서가 섞여 나온다.

## 4. 세 방식 비교

| 방식 | 기준 | 강점 | 약점 |
|---|---|---|---|
| **BM25** | 키워드(단어 겹침) | 임베딩 불필요로 빠름, 정확한 단어 매칭 | 동의어·다른 표현은 못 찾음 |
| **벡터** | 의미(임베딩 거리) | 뜻이 통하면 단어 달라도 찾음 | 임베딩·VectorDB 준비 필요 |
| **하이브리드** | 둘을 가중 결합 | 키워드+의미 모두 활용, 상호 보완 | 두 검색기·가중치 설정 필요 |

---

## 5. 오늘 한 줄 요약

> RAG의 검색은 세 방식이 있다. **BM25**(`BM25Retriever`)는 질문과 **단어가 겹치는** 문서를 찾는 키워드 검색으로, 빠르지만 동의어엔 약하다. **벡터 검색**(임베딩 + FAISS `as_retriever`)은 **의미가 비슷한** 문서를 찾아 표현이 달라도 잡지만 임베딩·DB 준비가 필요하다(저장·불러오기 `index_name`은 반드시 일치). **하이브리드**(`EnsembleRetriever`, `weights`)는 두 검색기를 가중 결합해 키워드와 의미를 함께 활용하며, 비중을 조절해 서로의 약점을 보완한다.
