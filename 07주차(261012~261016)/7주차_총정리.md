## A. 딥러닝 모델링

### A-1. 앙상블 — 여러 입력 합치기, 출력 분기

**앙상블**은 여러 입력 모델을 `Concatenate`로 합쳐 하나로 만든 모델이다. 지난주 기본형(입력 여러 개 → 출력 1개, 출력 분기)에 이어, 입력 1개를 공통 몸통에서 두 갈래로 나누는 형태까지 다뤘다.

```python
# keras69_ensemble4 — 입력 1개 → 공통 몸통 → 출력 2개 분기
input1 = Input(shape=(2,))
dense = Dense(30, activation='relu')(Dense(20, activation='relu')(Dense(10, activation='relu')(input1)))
output1 = Dense(5, activation='relu')(dense)   # 여기까지 공통, 아래서 갈라짐

b1 = Dense(10, activation='relu')(output1); last_output1 = Dense(1)(b1)   # 분기1
b2 = Dense(10, activation='relu')(output1); last_output2 = Dense(1)(b2)   # 분기2

model = Model(inputs=input1, outputs=[last_output1, last_output2])
model.fit(x_train, [y1_train, y2_train], ...)       # 출력 2개 → 타깃도 리스트
y1_pred, y2_pred = model.predict(x_test)            # 출력 2개 → 언패킹
```

- **함수형 API에서 같은 텐서를 두 층에 넘기면 그 지점에서 그래프가 갈라진다.** `output1`을 `b1`과 `b2`에 각각 넘기면 공통 몸통까지는 한 번만 계산해 공유하고, 그 뒤로 두 분기가 독립적으로 학습된다.
- **출력이 여러 개면 타깃은 `[y1, y2]` 리스트, 예측은 `y1,y2 = predict(...)`로 언패킹**한다. 리스트로 안 묶으면 "multiple values for batch_size" 에러, 한 변수로 받고 `[-1]` 하면 엉뚱한 출력이 잡힌다.

### A-2. 앙상블 실전 — 주식 시가 예측 (LSTM + Conv1D)

앙상블·시계열·전처리를 모두 쓰는 실전 과제다. **아모레·하이닉스를 앙상블해 내일 삼성전자 시가를 예측**한다. 조건은 ① 앙상블 ② LSTM·Conv1D 둘 다 ③ 입력 컬럼 종목당 5개 이상 ④ 가중치(weight) 저장이고, **시가는 예측 대상(y)이라 입력으로 쓰지 않는다.**

```python
# 주식 CSV 전처리 — 증권사 데이터 특성에 맞춤
def load_csv(path):
    df = pd.read_csv(path, encoding='cp949', thousands=',', index_col=0)  # 한글·천단위콤마
    df.index = pd.to_datetime(df.index)
    return df.sort_index()                   # 최신순(내림차순) → 과거→현재로 뒤집기

merged = am.join(hy, how='inner').join(sy, how='inner').dropna()   # 종목 날짜 교집합
```

- **CSV 로드 3종 세트**: `encoding='cp949'`(한글 컬럼), `thousands=','`("1,640,000"→숫자), `sort_index()`(최신순을 과거→현재로). 종목마다 거래일이 달라 `join(how='inner')`로 날짜 교집합만 맞춘다.
- **윈도우로 입력·정답 시점을 어긋나게 짝짓는다.** 10일치 `x[i:i+10]`를 보고 그 다음날 `y[i+10]`(삼성 시가)를 맞춘다. 입력 한 샘플은 `(10, 7)` 3차원이라 LSTM·Conv1D에 바로 들어간다.
- **두 입력에 서로 다른 시계열 층**을 쓴다(과제 조건): 아모레→LSTM, 하이닉스→Conv1D(출력 3차원이라 `Flatten`으로 2차원화) → `Concatenate` → Dense → 시가 1개 출력. 회귀라 마지막 `Dense(1)`은 활성화 함수 없이(선형), 손실은 mse, 평가는 R²·RMSE.
- **스케일러는 x만, 원본 전체로 fit**한다. 윈도우로 자른 배열이 아니라 자르기 전 원본으로 fit해야, 마지막 행(최근일)까지 포함돼 predict 코드와 기준이 일치한다.

**제출용 구조 — 원코드 / predict 분리 (weight만 제출).** weight 파일에는 학습된 숫자만 있고 모델 구조·스케일 규칙은 없다. 그래서 predict 코드는 ① 원코드와 똑같은 모델 구조를 다시 세우고 ② CSV로 스케일러를 똑같이 다시 계산한 뒤 `load_weights`로 가중치를 얹어 내일 시가 한 값만 출력한다. (전체 모델 `.keras`를 저장했다면 `load_model` 한 줄로 끝나지만, "weight만 제출" 조건 때문에 구조 재정의·스케일러 재계산이 생긴다.) 원코드·predict에서 입력 컬럼·타임스텝·모델 구조가 완전히 같아야 가중치가 맞물린다.

### A-3. 전이학습 — 사전학습 모델 가져다 쓰기

**전이학습(transfer learning)** 은 ImageNet 같은 대형 데이터로 미리 학습된 모델을 가져와 내 문제에 재사용하는 방법이다. 먼저 "가중치가 무엇이고, 동결이 무슨 뜻인지"부터 정리했다.

- **층 하나의 가중치는 kernel(가중치 행렬)·bias(편향) 2개**로 이뤄진다. `model.weights`는 전체 가중치 목록, `model.trainable_weights`는 그중 학습되는 것 목록이다.
- **`trainable = False`(동결)** 하면 `trainable_weights`가 0이 되고, 학습을 돌려도 가중치가 안 바뀐다. 동결한 채 학습하면 예측값이 초기 난수 상태 그대로 나온다.

```python
vgg16 = VGG16(weights='imagenet', include_top=False, input_shape=(32,32,3))
vgg16.trainable = False            # 특징 추출기 동결
model = Sequential([vgg16, Flatten(), Dense(100), Dense(100), Dense(10, activation='softmax')])
```

- **`weights='imagenet'`** 로 사전학습 가중치를 가져온다. **`include_top`** 은 뒤쪽 분류기(FC) 포함 여부로, `True`면 분류기 포함·입력 224×224 고정·출력 1000클래스(파라미터 약 138M), `False`면 특징 추출기만 남아 입력 크기를 바꿀 수 있고 내 분류기를 직접 붙인다(약 14.7M).
- **출력 뉴런 수 = 클래스 수**. cifar10은 `Dense(10)`, cifar100은 `Dense(100)`. `sparse_categorical_crossentropy`는 라벨을 출력 뉴런 인덱스로 쓰므로, 뉴런이 클래스 수보다 적으면 `loss: nan`이 난다.
- **동결 O vs X 비교(cifar10 실측)**: 동결 O는 acc 0.777, 동결 X(전체 재학습)는 0.10으로 사실상 실패. 작은 이미지·짧은 학습에서는 사전학습 특징을 그대로 쓰는 동결이 유리하다(추측: 1400만 개 가중치를 32×32·10에폭으로 다시 학습하기엔 부족해 수렴 못 함).

### A-4. 전이학습 심화 — 부분 동결 · 여러 모델 비교

```python
# 가중치 개수로 동결 확인 — VGG16(Conv 13층×2=26) + 내 Dense 2개×2=4 = 30개 중
print(len(model.weights))             # 30
print(len(model.trainable_weights))   # 4 (VGG 동결 → 내 Dense만 학습)

# 부분 동결 — 특정 층만 골라서
model.layers[2].trainable = False     # 내 모델의 특정 층만
vgg16.layers[11].trainable = False    # 사전학습 모델 '내부' 층만
```

- **부분 동결**: 전체(`vgg16.trainable`)가 아니라 `model.layers[i].trainable` / `vgg16.layers[i].trainable`로 원하는 층만 골라 얼린다. "앞쪽 일반 특징은 얼리고 뒤쪽만 다시 학습" 같은 세밀한 조절이 가능하다. `layer.trainable`을 DataFrame으로 뽑으면 어느 층이 동결됐는지 한눈에 확인된다.
- **여러 사전학습 모델 비교**: `keras.applications`에는 VGG·ResNet·DenseNet·Inception·MobileNet·NASNet·EfficientNet·Xception 등이 있다. 리스트에 담아 for문으로 돌려, 가중치 개수(keras75)에서 실제 학습·성능(keras76)까지 일괄 비교한다. `GlobalAveragePooling2D`·`verbose=0`·`warnings.filterwarnings("ignore")`로 가볍게 돌린다.
- **큰 모델이 늘 좋은 건 아니다(cifar10 실측)**: densenet201(0.586) > vgg19(0.536) > resnet50(0.327) > … > efficientnetb0(0.10). 데이터 특성과 모델 구조의 궁합이 성능을 가른다.

## B. RAG 심화

### B-1. 대화 기록을 기억하는 챗봇

지난주 RAG 챗봇(검색+생성+Gradio)에 **이전 대화를 기억하는 기능**을 더했다.

```python
prompt = ChatPromptTemplate.from_messages([
    ("system", "...컨텍스트 : {context}"),
    MessagesPlaceholder(variable_name="chat_history"),   # 지난 대화가 들어갈 자리
    ("human", "{input}")
])

def answer_invoke(message, history):   # Gradio가 이번 입력·지난 대화를 넘김
    chat_history = []
    for item in history:               # Gradio history(dict) → LangChain 메시지로 변환
        if item["role"] == "user":      chat_history.append(HumanMessage(content=item["content"]))
        elif item["role"] == "assistant": chat_history.append(AIMessage(content=item["content"]))
    return rag_chain.invoke({"input": message, "chat_history": chat_history})["answer"]
```

- **`MessagesPlaceholder`** 는 프롬프트 안에 지난 대화가 통째로 들어갈 빈 자리(`chat_history`)를 만든다. 매 질문마다 이전 대화를 함께 넣어 맥락을 이어간다.
- **Gradio의 history(딕셔너리)를 LangChain 메시지(`HumanMessage`/`AIMessage`)로 변환**해 `invoke`에 넘기는 것이 "기억"을 연결하는 핵심이다.

### B-2. 검색 품질 끌어올리기

같은 RAG 챗봇을 세 단계로 개선했다.

- **검색된 문서 확인**: `response["context"]`에는 답변 근거로 검색된 문서들이 담긴다. 이를 순회하며 `doc.metadata.get("source")`(출처)·`doc.page_content`(내용)를 출력하면, 모델이 엉뚱한 문서를 가져오는지 점검할 수 있다.
- **유사도 임계값**: 기본 검색기는 유사도와 무관하게 상위 k개를 무조건 가져온다. `search_type="similarity_score_threshold"` + `score_threshold=0.7`을 주면 기준 미만 문서를 버려, 관련 없는 질문에 억지로 문서를 들이대는 것을 막는다.
- **프롬프트(system) 규칙 세분화**: "컨텍스트로만 답하라"는 한 규칙이면 일상 인사에도 "답변할 수 없습니다"가 나온다. 규칙을 네 가지(이전 대화 참고 / 일상 대화 / 문서 질문 / 문서에 없는 질문)로 나눠 상황별로 다르게 답하게 한다. 코드는 그대로 두고 system 문구만 바꿔 챗봇 성격을 조정한다.

### B-3. 검색 방식 3가지 — BM25 · 벡터 · 하이브리드

검색(R) 단계 자체를 세 방식으로 다뤘다.

```python
# BM25 — 키워드(단어 겹침)
bm25_retriever = BM25Retriever.from_documents(texts); bm25_retriever.k = 3

# 벡터 — 의미(임베딩 거리)
vector_retriever = vector_store.as_retriever(search_kwargs={"k": 3})

# 하이브리드 — 둘을 가중 결합
from langchain_classic.retrievers import EnsembleRetriever
hybrid_retriever = EnsembleRetriever(retrievers=[bm25_retriever, vector_retriever], weights=[0.5, 0.5])
```

| 방식 | 기준 | 강점 | 약점 |
|---|---|---|---|
| **BM25** | 키워드(단어 겹침) | 임베딩 불필요로 빠름, 정확한 단어 매칭 | 동의어·다른 표현은 못 찾음 |
| **벡터** | 의미(임베딩 거리) | 뜻이 통하면 단어 달라도 찾음 | 임베딩·VectorDB 준비 필요 |
| **하이브리드** | 둘을 가중 결합 | 키워드+의미 모두 활용, 상호 보완 | 두 검색기·가중치 설정 필요 |

- **BM25**(Best Match 25)는 질문과 문서에 같은 단어가 얼마나 겹치는지로 점수를 매긴다. 빠르지만 동의어엔 약하다.
- **벡터 검색**은 임베딩으로 의미가 비슷한 문서를 찾아, 표현이 달라도 잡는다. 저장·불러오기 때 `index_name`이 반드시 같아야 한다(다르면 `No such file or directory`).
- **하이브리드**는 `EnsembleRetriever`로 두 검색기를 묶고 `weights`로 비중을 조절해, 키워드와 의미를 함께 활용한다.

## 7주차 한 줄 요약

> **앙상블**은 여러 입력을 `Concatenate`로 합치고 출력을 분기하는 구조로, 아모레·하이닉스를 앙상블해 삼성 시가를 예측하는 실전까지 다뤘다(LSTM+Conv1D, 시가는 입력 제외, CSV는 cp949·thousands·sort_index·inner join, 스케일러는 원본 전체 fit, weight만 저장하고 predict는 구조·스케일러를 재현해 load_weights). **전이학습**은 사전학습 모델(VGG16 등)을 가져와 특징 추출기를 동결하고 내 분류기만 학습하는 방법으로, 가중치(kernel·bias)·동결(trainable)·부분 동결·여러 모델 for문 비교까지 확장했다(큰 모델이 늘 좋은 건 아니다). **RAG 심화**는 대화 기억(`MessagesPlaceholder`), 검색 품질 개선(검색문서 확인·유사도 임계값·프롬프트 규칙), 검색 방식 3종(BM25 키워드·벡터 의미·하이브리드 결합)으로 정리된다.
