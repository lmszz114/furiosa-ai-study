## 1. keras71_trainable_weights — 가중치(weights)와 동결(trainable)

### 1-1. 가중치가 무엇으로 이루어지는가 (weights1)

```python
model = Sequential()
model.add(Dense(3, input_dim=1))
model.add(Dense(2))
model.add(Dense(1))

print(model.weights)             # 모델의 모든 가중치
print(model.trainable_weights)   # 그중 학습되는 가중치
print(len(model.weights))             # 6
print(len(model.trainable_weights))   # 6
```

**층 하나에 가중치는 두 종류다 — 가중치 행렬(kernel)과 편향(bias).** `Dense(3, input_dim=1)`은 입력 1개를 출력 3개로 보내므로 kernel은 `(1, 3)` 모양이고, 출력마다 더해지는 bias는 `(3,)` 모양이다. 즉 Dense 층 하나당 `[kernel, bias]` 2개의 가중치 묶음이 생긴다. 층이 3개면 2×3 = **6개**다. `len(model.weights)`가 6으로 나오는 이유다.

- `model.weights` : 모델이 가진 **모든** 가중치 목록
- `model.trainable_weights` : 그중 **학습(업데이트)되는** 가중치 목록

아무 설정도 하지 않으면 모든 가중치가 학습 대상이므로 두 값이 똑같이 6이다.

**`random.seed` / `np.random.seed` / `tf.random.set_seed`** 는 난수를 고정하는 장치다. 가중치는 처음에 난수로 초기화되는데, 셋을 같은 값(333)으로 고정하면 매번 같은 초기 가중치로 시작해 실행 결과가 재현된다. 파이썬 기본 난수·넘파이 난수·텐서플로 난수를 각각 쓰므로 세 개를 모두 고정한다.

### 1-2. 동결하면 학습 가중치가 0이 된다 (weights2)

```python
model.trainable = False     # 동결 ★
model.summary()

model.compile(loss='mse', optimizer='adam')
model.fit(x, y, batch_size=1, epochs=100)
y_predict = model.predict(x)
# [[0.4565795] [0.913159 ] [1.3704137] [1.826318 ] [2.283362 ]]
```

**`model.trainable = False` — 모델을 동결한다.** 동결하면 `trainable_weights`가 0개가 되고(summary의 Trainable params가 0), 학습(fit)을 돌려도 가중치가 전혀 바뀌지 않는다.

**동결 상태로 fit해도 예측값은 초기 가중치 그대로다.** 위 예측값은 x=1~5를 넣은 결과인데, 정답 y=1~5와 한참 다르다. 가중치가 처음 난수 상태에서 멈춰 있어 학습이 일어나지 않았기 때문이다. 학습이 되려면 가중치가 업데이트돼야 하는데 동결이 그걸 막는다.

### 1-3. 동결을 풀면 학습된다 (weights3)

```python
model.trainable = True
model.summary()
print(model.weights)

# [실습] weights로 손계산해서 1을 찾아보기
```

**`model.trainable = True`(기본값)** 이면 모든 가중치가 학습 대상으로 돌아온다. x와 y가 똑같은 `[1,2,3,4,5]`이므로 이 모델이 학습으로 찾아야 할 관계는 `y = x`, 즉 입력을 그대로 내보내는 것이다. 각 층의 kernel·bias가 합쳐져 최종적으로 기울기 1, 절편 0에 가까운 변환이 되도록 가중치가 조정된다. "weights로 손계산해서 1을 찾는다"는 것은, 학습된 각 층의 kernel 값을 순서대로 곱해 입력 1이 출력 1로 나오는지 직접 계산해 확인해 보라는 실습이다.

## 2. keras72_vgg16_include_top — 사전학습 모델 VGG16

**전이학습(transfer learning)** 은 큰 데이터로 미리 학습된 모델을 가져와 내 문제에 재사용하는 방법이다. VGG16은 2014년 ILSVRC 대회에서 ImageNet(1000종 분류) 데이터로 학습된 CNN이다. 이 모델이 이미 배워 둔 "이미지의 일반적 특징을 뽑는 능력"을 가져다 쓴다.

```python
from keras.applications import VGG16

model = VGG16(
    # weights='imagenet',
    include_top=False,     # 분류기 제거, 특징 추출기만
    input_shape=(100, 100, 3),
)
model.summary()
```

**`weights='imagenet'` — ImageNet으로 학습된 가중치를 가져온다.** 이 옵션이 전이학습의 핵심이다. None이면 구조만 가져오고 가중치는 난수로 초기화된다.

**`include_top` — 꼭대기(분류기 부분)를 포함할지 여부.** VGG16은 크게 앞쪽 "특징 추출기(Conv/Pooling 층들)"와 뒤쪽 "분류기(Flatten + Dense)"로 나뉜다. `include_top`은 이 뒤쪽 분류기를 붙일지 정한다.

| 구분 | include_top=True (기본) | include_top=False |
|------|------|------|
| 분류기(FC) | 포함 (fc1, fc2, predictions) | 제거 — 특징 추출기만 |
| input_shape | **(224, 224, 3) 고정** | **원하는 크기로 변경 가능** |
| 출력 | 1000개 클래스 | 특징 맵 (예: 3×3×512) |
| 파라미터 수 | 약 138,357,544 | 약 14,714,688 |

- **include_top=True** 는 원래 분류기까지 그대로다. 분류기(Dense)는 입력 크기가 고정이라 input_shape를 224×224×3에서 바꿀 수 없고, 출력도 ImageNet의 1000개 클래스에 묶인다.
- **include_top=False** 는 분류기를 떼어내 특징 추출기만 남긴다. Dense가 없으니 input_shape를 내 데이터 크기로 바꿀 수 있고, 떼어낸 자리에 내 문제에 맞는 분류기(Dense)를 직접 붙인다. 파라미터가 138M → 14.7M로 줄어드는 것은 거대한 FC 층(fc1·fc2)이 빠졌기 때문이다.

전이학습으로 내 데이터를 분류할 때는 보통 `include_top=False`로 특징 추출기만 가져와 뒤에 내 Dense 분류기를 붙인다.

## 3. keras73_vgg16_cifar10 / cifar100 — 전이학습으로 분류

VGG16 특징 추출기 뒤에 내 분류기를 붙여 cifar10(10종), cifar100(100종)을 분류한다. 실습 목적은 **특징 추출기를 동결(trainable=False)했을 때와 풀었을 때(True)의 성능·시간 비교**다.

```python
######## 스케일링 ########
x_train = x_train/255.    # 0~255 픽셀값을 0~1로
x_test = x_test/255.

#2. 모델
vgg16 = VGG16(
    weights='imagenet',
    include_top=False,
    input_shape=(32, 32, 3),
)

# vgg16.trainable = True    # 동결 X — VGG 특징 추출기까지 전부 학습
vgg16.trainable = False     # 동결 O — 특징 추출 가중치는 학습 안 함

model = Sequential()
model.add(vgg16)            # 가져온 특징 추출기를 한 덩어리 층처럼 쌓는다
model.add(Flatten())
model.add(Dense(100))
model.add(Dense(100))
model.add(Dense(10, activation='softmax'))   # cifar10: 10 / cifar100: 100
```

**이미지 스케일링은 255로 나눈다.** 픽셀값은 0~255 정수다. 255로 나눠 0~1로 맞추면 학습이 안정된다. 이미지는 최솟값 0, 최댓값 255가 정해져 있어 MinMaxScaler 없이 나눗셈만으로 충분하다.

**가져온 VGG16을 `model.add(vgg16)`로 통째로 쌓는다.** 사전학습 모델 하나를 하나의 층처럼 Sequential에 넣고, 그 뒤에 Flatten → Dense로 내 분류기를 잇는다. 특징 추출기의 출력(3×3×512 특징 맵)을 Flatten으로 펴서 Dense로 분류한다.

**출력층 뉴런 수 = 클래스 수.** cifar10은 `Dense(10, softmax)`, cifar100은 `Dense(100, softmax)`다. sparse_categorical_crossentropy는 정답 라벨(0~클래스수-1) 값을 출력 뉴런의 인덱스로 바로 쓰므로, 뉴런 수가 클래스 수보다 적으면 없는 자리를 가리켜 `loss: nan`이 난다. (cifar100에서 출력을 10으로 두면 라벨 10~99가 범위를 벗어나 nan이 나는 것이 그 경우다.)

**`vgg16.trainable` — 특징 추출기를 동결할지.** 전이학습의 핵심 선택이다.

- `False`(동결) : ImageNet으로 배운 특징 추출 가중치를 그대로 두고, **뒤에 붙인 내 분류기(Dense)만 학습**한다. 이미 잘 학습된 특징을 재사용하므로 적은 학습으로도 성능이 잘 나온다.
- `True`(비동결) : VGG16의 1400만 개 넘는 가중치까지 전부 다시 학습한다.

**실습 결과.**

cifar10 (epochs=10, batch_size=100):

| 구분 | acc | 훈련 시간 |
|------|-----|-----------|
| 동결 X (trainable=True) | 0.10 | 112.99초 |
| 동결 O (trainable=False) | 0.7769 | 117.64초 |

cifar100 (epochs=60, batch_size=550, 동결 O): acc 0.3464 / 232.63초

**결과 해석.** 동결했을 때(0.777)가 동결하지 않았을 때(0.10)보다 압도적으로 높다. 동결하지 않은 쪽의 0.10은 10개 클래스에서 찍기(1/10) 수준으로, 학습이 제대로 되지 않았다는 뜻이다. (추측: 32×32의 작은 이미지로 1400만 개 가중치 전체를 10 에폭 만에 학습시키기엔 턱없이 부족해 수렴하지 못한 것으로 보인다.) 사전학습된 특징을 그대로 쓰는 동결 방식이 이 조건에서 훨씬 유리하다는 것을 보여준다.

**EarlyStopping의 `patience=999`.** 사실상 조기종료가 걸리지 않아 지정한 epochs를 전부 돈다. 동결 O/X를 같은 epoch·batch로 끝까지 돌려 공정하게 비교하려는 설정이다.

## 4. rag22_Gradio — RAG 챗봇 고도화

전날 만든 RAG 챗봇(FAISS 검색 + Gradio + 대화기록)을 바탕으로 세 가지를 차례로 개선한다. 데이터 적재·임베딩·FAISS 로드·체인 구성·Gradio 연결은 앞과 같고, 아래 달라진 부분만 정리한다.

### 4-1. rag22_1 — 실제 검색된 문서 확인

답변만 받던 함수에, 모델이 실제로 어떤 문서를 근거로 삼았는지 터미널에 출력하는 부분을 더한다.

```python
response = rag_chain.invoke({"input": message, "chat_history": chat_history})

# 터미널에서 실제 검색된 문서 2개 확인
for i, doc in enumerate(response["context"], start=1):
    print(f"\n검색 문서 {i}")
    print("출처: ", doc.metadata.get("source"))
    print("내용: ", doc.page_content)
return response["answer"]
```

**`response["context"]` — 검색기가 찾아 온 문서들.** `create_retrieval_chain`의 결과에는 최종 답변(`answer`) 외에, 그 답변의 근거로 검색된 문서들이 `context`에 담긴다. 이걸 순회하며 `doc.metadata.get("source")`(출처 파일)와 `doc.page_content`(문서 내용)를 출력하면, 모델이 어떤 근거로 답했는지 확인할 수 있다. RAG가 엉뚱한 문서를 가져오는지 점검하는 용도다.

`enumerate(..., start=1)`은 순번을 1부터 매겨 "검색 문서 1, 2 …"로 보기 좋게 출력하기 위한 것이다.

### 4-2. rag22_2 — 유사도 임계값으로 검색 거르기

검색기를 "상위 k개 무조건 반환"에서 "유사도가 기준 이상인 것만 반환"으로 바꾼다.

```python
# 기존: retriever = db.as_retriever(search_kwargs={"k": 2})
retriever = vector_store.as_retriever(
    search_type = "similarity_score_threshold",
    search_kwargs={
        "k": 2,
        "score_threshold": 0.7   # 유사도 0.7 미만은 검색에서 제외
    }
)
```

**`search_type="similarity_score_threshold"` — 유사도 점수에 문턱을 둔다.** 기본 검색기는 질문과 가장 가까운 상위 k개를 유사도와 무관하게 무조건 가져온다. 이 방식은 질문과 전혀 관련 없는 문서도 "그나마 가까운 2개"로 끌려오는 문제가 있다. `score_threshold=0.7`을 주면 유사도가 0.7 이상인 문서만 남기고, 기준에 못 미치면 k개가 안 되더라도 버린다. 관련 없는 질문에 억지로 문서를 들이대는 것을 막아, "주어진 정보로는 답변할 수 없습니다"로 이어지게 한다.

### 4-3. rag22_3 — 프롬프트(system) 규칙 강화

문서 전용으로 답하던 프롬프트를, 상황을 구분해 답하도록 규칙을 세분화한다.

```python
prompt = ChatPromptTemplate.from_messages([
    ("system", """
    당신은 강력한 AI 챗봇입니다.
    다음 규칙에 따라 답변하세요.
    1. 이전 대화에서 확인할 수 있는 정보는 이전 대화를 참고하여 답변하세요.
    2. 일반적인 인사나 일상 대화는 자연스럽게 답변하세요.
    3. 문서에 관한 질문은 제공된 컨텍스트를 근거로 답변하세요.
    4. 문서에 관한 질문인데 컨텍스트에 관련 정보가 없다면 "주어진 정보로는 답변할 수 없습니다"라고 답변하세요.

    컨텍스트 : {context}
    """),
    MessagesPlaceholder(variable_name="chat_history"),
    ("human", "{input}")
])
```

**system 프롬프트가 챗봇의 행동 규칙을 정한다.** 이전의 프롬프트는 "컨텍스트로만 답하고, 없으면 답변 불가"라는 한 가지 규칙뿐이었다. 그래서 "안녕"같은 일상 인사에도 "주어진 정보로는 답변할 수 없습니다"로 답하는 문제가 있었다. 규칙을 네 가지로 나눠, 대화 종류(이전 대화 참고 / 일상 대화 / 문서 질문 / 문서에 없는 질문)에 따라 다르게 답하도록 지시한다. 이렇게 하면 일상 대화는 자연스럽게 받고, 문서 질문만 컨텍스트 기반으로 엄격히 답하며, 근거가 없을 때만 답변 불가로 처리한다. 코드 구조는 그대로 두고 **system 문구만 바꿔 챗봇의 성격을 조정**하는 것이 이 단계의 핵심이다.
