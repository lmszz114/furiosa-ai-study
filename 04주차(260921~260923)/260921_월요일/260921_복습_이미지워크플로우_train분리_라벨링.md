## 1. 이미지 분류 전체 워크플로우 (파일 3단계)

이미지 분류 실습은 파일이 여러 개로 나뉜다. **오래 걸리는 작업(수치화·학습)은 한 번 하고 저장 → 필요할 때 불러와 쓰는** 구조이기 때문이다. 전체 흐름:

```
[① save 파일]  keras46_xx_save
  폴더 이미지 → ImageDataGenerator 수치화 → (필요 시 train_test_split) → np.save(.npy) → exit()
        │  "이미지를 숫자로 바꿔 .npy로 저장"
        ▼
[② load·train 파일]  keras47_xx_load
  np.load(.npy) → 모델 구성 → 훈련 → model.save(.keras)  (또는 MCP/가중치 저장)
        │  "저장된 데이터로 학습하고, 학습된 모델을 .keras로 저장"
        ▼
[③ predict 파일]  keras49_xx
  load_model(.keras) + np.load(내 사진.npy) → predict → 판정
           "학습된 모델 + 내 사진을 불러와 예측"

[내 사진 준비]  keras48_img_to_array
  내 사진.jpg → img_to_array 수치화 → np.save(내 사진.npy)   (③에서 사용)
```

- 각 화살표에서 **저장(.npy / .keras)** 이 일어나고, 다음 파일에서 **불러오기(np.load / load_model)** 로 이어받는다.
- 이 구조를 이해하면 "파일이 왜 이렇게 많은지"가 풀린다: 학습(몇 분 소요)과 수치화를 매번 반복하지 않으려고 결과를 저장해두는 것이다.

### 저장 두 종류 구분 (제일 헷갈리는 부분)
| 저장 | 저장 대상 | 함수 | 확장자 |
|---|---|---|---|
| **데이터 저장** | 이미지 수치화 결과 | `np.save` | .npy |
| **모델 저장** | 학습된 모델(구조 + 가중치) | `model.save` | .keras |

- `np.save`는 **데이터**(이미지 숫자), `model.save`는 **모델**(학습 결과). 완전히 다른 것이다.
- ③ predict 파일에서는 **둘 다** 불러온다: 모델(`load_model`) + 내 사진(`np.load`).

## 2. train / test 나누기 — 폴더가 안 나뉜 경우

지금까지는 데이터가 `training_set` / `test_set`으로 **이미 나뉘어** 제공됐다(cat_dog 등). 그러나 horse_human·rps·men_women은 **클래스 폴더만 있고 train/test 구분이 없다.**

```
horse_human/
├── horses/     ← 클래스 폴더만 있음 (train/test 구분 없음)
└── humans/
```

이 경우 **전체를 한 번에 불러온 뒤 `train_test_split`으로 직접 나눈다.**

```python
# 1. 통째로 불러오기 (flow_from_directory 한 번)
xy = train_datagen.flow_from_directory(
    path, target_size=(200,200), batch_size=10000,   # 전체를 한 배치에 담기(넉넉히 크게)
    class_mode='binary', color_mode='rgb', shuffle=True)
x = xy[0][0]     # 전체 이미지
y = xy[0][1]     # 전체 라벨

# 2. train_test_split으로 나누기 (표 데이터 때와 동일)
from sklearn.model_selection import train_test_split
x_train, x_test, y_train, y_test = train_test_split(
    x, y, train_size=0.8, random_state=1024, stratify=y)
```

- **핵심 규칙: 폴더에 train/test가 있으면 각각 불러오고, 없으면 통째로 불러와 `train_test_split`으로 나눈다.**
- 나누는 방법은 표 데이터 때와 **완전히 동일**하다(이미지가 4차원일 뿐). `stratify=y`로 클래스 비율을 유지한다.

## 3. 자동 라벨링 규칙과 predict 해석

### 라벨은 폴더 이름 알파벳순으로 정해진다
`flow_from_directory`는 **하위 폴더 이름을 알파벳(사전) 순으로 정렬해 0, 1, 2… 를 매긴다.**
```
cat_dog/  → cats(c 먼저)=0, dogs(d 나중)=1
horse_human/ → horses=0, humans=1
men_women/ → men=0, women=1
```
- 이 대응표는 추측하지 말고 **코드로 확인**한다:
```python
print(xy.class_indices)   # {'cats': 0, 'dogs': 1} 처럼 폴더명↔라벨 대응 출력
```

### 이진분류 predict 해석 (sigmoid 출력)
출력층이 sigmoid라 `predict` 결과는 **0~1 사이 숫자 하나**이며, 이는 **"라벨 1(알파벳 뒤 폴더)일 확률"** 이다.
```
predict = 0.9  → 라벨 1에 가까움 (예: dog)
predict = 0.1  → 라벨 0에 가까움 (예: cat)
predict = 0.5  → 반반
```
- **0.5 기준**으로 0/1을 가른다. `np.round`를 씌우면 명확해진다.
```python
y_predict = np.round(model.predict(x_test))   # 0 또는 1
# 0 → 알파벳 앞 폴더(cat/horse/men), 1 → 알파벳 뒤 폴더(dog/human/women)
```
- 즉 "내 사진 predict 결과가 0에 가까우면 앞 폴더 클래스, 1에 가까우면 뒤 폴더 클래스"다. 어느 폴더가 0인지는 `class_indices`로 확인한다.

### 참고 — rps는 다중분류
rock·paper·scissors는 3클래스이므로 **다중분류**다(sigmoid가 아니라 softmax, `class_mode='categorical'`, 예측은 argmax). horse_human·cat_dog·men_women은 2클래스라 이진분류.

## 4. keras48_img_to_array — 내 사진 한 장을 수치화

폴더 여러 장이 아니라 **내 사진 한 장**을 모델에 넣으려면 직접 수치화해야 한다.
```python
from tensorflow.keras.preprocessing.image import load_img, img_to_array
import numpy as np

img = load_img(path + "lhy.jpg", target_size=(100,100))   # 이미지 한 장 불러오기(PIL 이미지)
print(type(img))   # <class 'PIL.Image.Image'>

arr = img_to_array(img)          # PIL 이미지 → numpy 배열
print(arr.shape)                 # (100, 100, 3)

arr = np.expand_dims(arr, axis=0)   # 차원 확장 → (1, 100, 100, 3)
arr = arr / 255.                    # 스케일링

np.save(np_path + 'keras49_me.npy', arr=arr)   # 내 사진을 .npy로 저장 (predict 파일에서 사용)
```
- **`load_img`**: 이미지 한 장을 불러올 때 편한 함수(결과는 PIL 이미지). `target_size`로 크기를 학습 때와 맞춘다.
- **`img_to_array`**: PIL 이미지를 numpy 배열 `(100,100,3)`로 바꾼다.
- **`np.expand_dims(arr, axis=0)`**: 맨 앞에 차원을 하나 추가해 `(1,100,100,3)`으로 만든다. 모델은 **4차원(샘플, 높이, 너비, 채널)** 을 받는데, 한 장은 `(100,100,3)` 3차원이라 **샘플 차원(1)을 직접 붙여줘야** 한다. (flow_from_directory는 여러 장이라 자동으로 4차원이 되지만, 한 장 직접 불러올 때는 수동으로 추가.)
- 스케일링(`/255.`)도 학습 때와 똑같이 맞춰야 한다.

## 5. keras50_flow1 — 데이터 증폭(flow)

이미지 한 장(또는 배열)에서 **변형된 이미지를 여러 장 만들어내는** 증폭 실습이다. `flow_from_directory`가 폴더에서 읽는다면, **`flow`는 이미 있는 배열에서** 증강한다.
```python
from tensorflow.keras.preprocessing.image import ImageDataGenerator

datagen = ImageDataGenerator(
    rescale=1./255,
    horizontal_flip=True, vertical_flip=True,
    rotation_range=60, zoom_range=0.1, fill_mode='nearest',
)

it = datagen.flow(arr, batch_size=1)   # 배열 arr에서 증강 이미지를 만드는 반복자

print(next(it).shape)   # (1, 100, 100, 3)  — 증강된 이미지 한 장
```
- **`datagen.flow(배열)`**: 배열에서 증강 이미지를 만드는 반복자(iterator)를 반환한다.
- **`next(it)`**: 다음 증강 이미지를 꺼낸다. 부를 때마다 뒤집기·회전 등이 **랜덤 적용된 다른 이미지**가 나온다. (파이썬 3.11부터 `it.next()`가 `next(it)`로 바뀌었다.)
- `plt.subplots`로 여러 장을 그려보면, 한 장의 원본에서 다양한 변형이 생성되는 것을 눈으로 확인할 수 있다.

## 7. 오늘 한 줄 요약

> 이미지 분류는 **① 수치화·저장(np.save) → ② 불러와 학습·모델저장(model.save) → ③ 모델·사진 불러와 predict** 의 3단계 파일로 이어진다. 폴더가 train/test로 안 나뉘면 **통째로 불러와 `train_test_split`** 으로 나누고, 라벨은 **폴더 알파벳순으로 0·1**이 매겨진다(`class_indices`로 확인). sigmoid predict 값은 **0에 가까우면 앞 폴더·1에 가까우면 뒤 폴더** 클래스다.
> 내 사진 한 장은 `load_img → img_to_array → expand_dims(4차원) → /255`로 수치화하고, `datagen.flow`로 한 장에서 여러 변형 이미지를 만들 수 있다.
