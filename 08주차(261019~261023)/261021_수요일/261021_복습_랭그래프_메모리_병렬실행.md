## 1. lg07_ToolNode_graph02 — 그래프를 화면에 그림으로 출력

어제 lg07은 그래프 그림을 **파일로 저장**(`open`/`write`)했다. 이번에는 파일로 저장하지 않고 **화면 창에 바로 띄운다.** 그래프 구성(도구 호출 + 조건부 엣지)은 어제와 같고, 마지막 출력 부분만 바뀐다.

```python
import matplotlib.pyplot as plt
from PIL import Image
from io import BytesIO

png_data = graph.get_graph().draw_mermaid_png()   # 그래프를 PNG 이미지 데이터로

img = Image.open(BytesIO(png_data))   # 메모리 속 PNG 데이터를 이미지로 열기

plt.figure(figsize=(12, 8))
plt.imshow(img)       # 이미지를 그래프 창에 표시
plt.axis("off")       # 축(눈금) 숨기기
plt.show()            # 창 띄우기
```

- **`draw_mermaid_png()`** 가 돌려주는 것은 파일이 아니라 **PNG 이미지의 바이트 데이터**(메모리상의 그림 조각)다.
- **`BytesIO(png_data)`** 는 이 바이트 데이터를 "파일인 것처럼" 다루게 해준다. 디스크에 저장하지 않고도 `Image.open`이 파일을 열듯 읽을 수 있다. (`io.BytesIO`는 메모리 위의 임시 파일이라고 보면 된다.)
- **`matplotlib`(plt)으로 그림을 화면에 띄운다**: `imshow`로 이미지를 얹고, `axis("off")`로 눈금을 끄고, `show()`로 창을 연다. 어제 본 그래프 그림을 저장 없이 즉석에서 확인하는 방식이다.

## 2. lg08_Memory — 대화를 기억시키기 (체크포인터)

### 2-1. lg08_01 — 메모리가 없으면 기억하지 못한다

```python
# 첫번째 질문
response = graph.invoke({"messages" : [("user", "내 이름은 윤영선이야.")]})
print(response["messages"][-1].content)

print("==================== 두번째 질문 ====================")
# 두번째 질문
response = graph.invoke({"messages" : [("user", "내 이름이 뭐야.")]})
print(response["messages"][-1].content)   # 이름을 기억하지 못함
```

**`graph.invoke`는 기본적으로 매번 독립적으로 실행된다.** 첫 번째 질문에서 "내 이름은 윤영선"이라고 알려줘도, 두 번째 `invoke`는 **완전히 새 실행**이라 앞의 대화를 모른다. 그래서 "내 이름이 뭐야"에 답하지 못한다. 그래프 자체에는 대화를 이어서 기억하는 기능이 기본으로 켜져 있지 않다.

(지난주 Gradio 챗봇에서는 대화 기록을 `chat_history`로 직접 넘겨 기억시켰다. 이번에는 그래프 자체에 기억 장치를 다는 방법을 쓴다.)

### 2-2. lg08_02 — 체크포인터를 달면 기억한다

```python
from langgraph.checkpoint.memory import InMemorySaver   # ① 메모리 도구 가져오기

# ... (그래프 구성은 동일)

# ② 컴파일할 때 체크포인터를 단다
memory = InMemorySaver()
graph = graph_builder.compile(checkpointer=memory)

# ③ 실행할 때 대화방 번호(thread_id)를 준다
config = {"configurable" : {"thread_id" : "user01"}}

response = graph.invoke({"messages" : [("user", "내 이름은 윤영선이야.")]}, config=config)
print(response["messages"][-1].content)

print("==================== 두번째 질문 ====================")
response = graph.invoke({"messages" : [("user", "내 이름이 뭐야.")]}, config=config)
print(response["messages"][-1].content)   # "윤영선" 이라고 기억해서 답함
```

**체크포인터(checkpointer)는 그래프가 주고받은 상태(대화)를 저장해 두는 '기억 장치'다.** 세 가지만 추가하면 된다.

- **① `InMemorySaver`** — 상태를 저장할 메모리 도구다. 이름 그대로 **메모리(RAM)에 저장**하므로, 프로그램을 끄면 사라진다(실습·단기 대화용). 디스크나 DB에 영구 저장하려면 다른 종류의 체크포인터를 쓴다.
- **② `compile(checkpointer=memory)`** — 그래프를 만들 때 이 기억 장치를 연결한다. 이제 그래프는 실행할 때마다 상태를 저장하고, 다음 실행 때 불러온다.
- **③ `config`의 `thread_id`** — **대화방을 구분하는 번호**다. 같은 `thread_id`("user01")로 실행하면 같은 대화방이라 이전 대화가 이어지고, 다른 `thread_id`를 주면 별개의 새 대화가 된다. (한 챗봇으로 여러 사용자의 대화를 섞이지 않게 나눠 관리할 때 쓴다.)

이 셋을 붙이면 두 번째 질문에서도 첫 질문의 "윤영선"을 기억해 답한다. **체크포인터가 `thread_id`별로 대화 상태를 쌓아 두기 때문이다.**

## 3. lg09_Parallel_execution — 여러 노드를 동시에 실행하고 합치기

지금까지 그래프는 한 노드가 끝나야 다음 노드로 가는 **순차 실행**이었다. 서로 의존하지 않는 작업이라면 **동시에(병렬) 실행**해 시간을 아낄 수 있다. 핵심은 **START에서 여러 노드로 갈라져 나갔다가, 한 노드로 다시 모여 합치는** 구조다.

### 3-1. lg09_merge1 — 병렬 구조의 뼈대

```python
class State(TypedDict):
    question : str
    search_result : str      # 검색 노드가 쓰는 칸
    analysis_result : str    # 분석 노드가 쓰는 칸
    final_result : str

def search_agent(state : State):
    print("검색 에이전트 실행")
    return {"search_result" : "엔비디아는 AI GPU 시장의 주요 기업이다."}

def analysis_agent(state : State):
    print("분석 에이전트 실행")
    return {"analysis_result" : "AI 반도체 수요 증가가 성장 요인이다."}

def merge_agent(state : State):
    result = state["search_result"] + "\n" + state["analysis_result"]
    return {"final_result" : result}

builder.add_node("search", search_agent)
builder.add_node("analysis", analysis_agent)
builder.add_node("merge", merge_agent)

# 병렬 실행 — START에서 두 노드로 동시에 갈라짐
builder.add_edge(START, "search")
builder.add_edge(START, "analysis")
# 병합 — 두 노드가 merge로 모임
builder.add_edge("search", "merge")
builder.add_edge("analysis", "merge")
builder.add_edge("merge", END)
```

```
            ┌→ (search)   ─┐
[START] ────┤              ├→ (merge) → [END]
            └→ (analysis) ─┘
```

- **START에서 두 노드로 엣지를 그으면 그 노드들이 동시에(병렬) 실행된다.** `search`와 `analysis`는 서로 기다리지 않고 함께 돌아간다.
- **두 노드가 한 노드(`merge`)로 모이면, `merge`는 둘 다 끝난 뒤에 실행된다.** 그래서 `merge`에서 두 결과를 합칠 수 있다. 이것이 "병렬로 나눠 일하고 마지막에 합치기"다.
- **병렬 노드는 상태의 서로 다른 칸에 쓴다.** `search`는 `search_result`에, `analysis`는 `analysis_result`에 각각 저장한다. 칸을 나눠 두면 동시에 실행돼도 **같은 칸에 동시에 쓰려다 충돌하는 일이 없다.** (만약 둘이 같은 칸에 쓰면, 그 칸에 합치는 규칙(리듀서)이 없는 한 충돌이 난다. 그래서 병렬에서는 칸 설계가 중요하다.) `merge`가 두 칸을 읽어 `final_result`로 합친다.

### 3-2. lg09_merge2 — 실전: 웹 검색 + LLM 분석을 동시에

구조는 merge1과 같고, 두 노드가 **실제 일**을 한다. 검색 노드는 웹을 검색하고, 분석 노드는 LLM이 자체 지식으로 분석한다. 같은 질문을 **두 방식으로 동시에** 처리해 합치는 패턴이다.

```python
class State(TypedDict):
    messages : Annotated[list, add_messages]
    search_result : str      # search_agent 가 저장 → merge_agent 가 사용
    analysis_result : str    # analysis_agent 가 저장 → merge_agent 가 사용

def search_agent(state : State):          # 웹 검색 담당
    question = state["messages"][-1].content
    result = web_search.invoke({"query" : question})
    return {"search_result" : str(result)}

def analysis_agent(state : State):        # LLM 자체 분석 담당
    question = state["messages"][-1].content
    response = llm.invoke(f"다음 질문을 기존 지식을 바탕으로 분석해줘.\n{question}")
    return {"analysis_result" : response.content}

def merge_agent(state : State):           # 둘을 합쳐 최종 답으로
    result = state["search_result"] + "\n\n====================\n" + state["analysis_result"]
    return {"messages" : [("assistant", result)]}
```

- **`search_agent`는 웹 검색(최신·실시간 정보), `analysis_agent`는 LLM 자체 지식(분석·배경)** 을 맡아 서로 다른 관점의 결과를 만든다. 둘은 의존 관계가 없어 병렬로 동시에 돈다.
- 각자 자신의 칸(`search_result`·`analysis_result`)에 저장하고, **`merge_agent`가 둘을 이어 붙여 `messages`에 최종 답변으로 넣는다.** `("assistant", result)`는 "AI가 한 답"으로 메시지에 쌓인다.
- "질문을 던지면 웹 검색 결과와 모델 분석을 **동시에 뽑아 한 답으로 합쳐 주는**" 흐름으로, 병렬 실행이 실제로 쓸모 있게 쓰이는 예다.

## 4. 한 줄 요약

> **그래프 그림 출력**은 `draw_mermaid_png()`로 얻은 이미지 데이터를 `BytesIO`(메모리 속 임시 파일)로 감싸 `matplotlib`로 화면에 띄운다(저장 대신 즉석 확인). **메모리(체크포인터)** 는 그래프가 대화를 기억하게 하는 장치로, 기본 `invoke`는 매번 독립 실행이라 기억하지 못하지만 `InMemorySaver`를 `compile(checkpointer=...)`로 달고 실행 때 `config`의 `thread_id`(대화방 번호)를 주면 그 방의 대화를 이어 기억한다(InMemorySaver는 RAM 저장이라 프로그램을 끄면 사라짐). **병렬 실행**은 `START`에서 여러 노드로 갈라 동시에 돌리고 한 노드로 모아 합치는 구조로, 병렬 노드는 상태의 서로 다른 칸에 써서 충돌을 피하고 `merge` 노드가 그 칸들을 읽어 합친다(예: 웹 검색 + LLM 분석을 동시에 수행 후 통합).
