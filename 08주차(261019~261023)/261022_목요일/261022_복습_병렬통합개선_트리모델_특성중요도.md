## 1. lg09_merge3 — 병렬 결과를 LLM이 '종합'하도록 개선

어제 병렬 실행에서는 검색 노드와 분석 노드의 결과를 `merge` 노드가 **기계적으로 이어 붙였다**(문자열 + 문자열). 이번에는 `merge` 노드가 두 결과를 **LLM에게 넘겨 종합한 최종 답변**을 만들게 바꾼다. 그래프 구조(병렬 → 병합)는 그대로다.

```python
def merge_agent(state : State):   # 결과 통합 에이전트 (개선)
    print("결과 통합 에이전트 실행")

    prompt = f"""
다음 두 결과를 종합하여 최종 답변을 작성해줘.

[웹 검색 결과]
{state["search_result"]}

[AI 분석 결과]
{state["analysis_result"]}

검색 결과를 우선적으로 참고하고,
최신 정보와 기존 분석을 구분해서 설명해줘.
"""
    response = llm.invoke(prompt)
    return {"messages" : [response]}
```

- **merge 노드가 LLM을 한 번 더 호출해 두 결과를 녹여낸다.** 단순히 붙이기만 하면 "검색 결과 따로, 분석 따로"인 거친 답이 되지만, LLM에게 종합을 맡기면 두 내용을 **하나의 매끄러운 답변**으로 재작성한다.
- **프롬프트로 종합 방식을 지시한다**: "검색 결과를 우선 참고", "최신 정보와 기존 분석을 구분". 이렇게 통합 기준을 주면, 실시간 검색 내용과 모델의 배경지식이 섞이지 않고 역할이 구분된 답이 나온다.
- 병렬로 서로 다른 관점(웹 검색·자체 분석)을 모으고, 마지막에 LLM이 **편집자처럼 종합**하는 흐름이다. 병렬 실행의 결과를 실제로 쓸모 있게 마무리하는 패턴이다.

```bash

```

- **가상환경을 따로 두는 이유**: 프로젝트마다 쓰는 라이브러리·버전이 달라, 한 환경에 다 섞으면 충돌이 난다. `conda create -n <이름> python==<버전>`으로 격리된 환경을 만들어 그 안에만 필요한 패키지를 설치한다.
- **scikit-learn(사이킷런)** 은 머신러닝의 표준 도구 모음으로, 데이터셋·모델·전처리·평가가 다 들어 있다. **xgboost**는 성능 좋은 부스팅 모델 라이브러리다.

## 3. m01_feature_importances01 — 특성 중요도 (분류, 트리 모델 4종)

트리 기반 모델 네 가지로 iris(붓꽃) 품종을 분류하고, 각 모델이 알려주는 **특성 중요도**를 비교한다.

```python
from sklearn.datasets import load_iris
from sklearn.tree import DecisionTreeClassifier
from sklearn.ensemble import RandomForestClassifier, GradientBoostingClassifier
from xgboost import XGBClassifier

x, y = load_iris(return_X_y=True)   # (150, 4) — 꽃잎·꽃받침 길이/너비 4개 특성, 품종 3종
x_train, x_test, y_train, y_test = train_test_split(
    x, y, train_size=0.8, random_state=123, stratify=y)

models = [DecisionTreeClassifier(random_state=123), RandomForestClassifier(random_state=123),
          GradientBoostingClassifier(random_state=123), XGBClassifier(random_state=123)]

for model in models:
    model.fit(x_train, y_train)
    print("=================", model.__class__.__name__, "=================")
    print("acc : ", model.score(x_test, y_test))
    print(model.feature_importances_)   # 특성 중요도
```

**트리 기반 모델 4종.** 모두 "데이터를 조건으로 나눠가며(가지치기) 예측"하는 트리를 바탕으로 한다.

- **DecisionTree(결정 트리)**: 기본 단위. "꽃잎 길이가 X보다 큰가?"처럼 질문을 나눠가며 분류한다. 한 그루라 단순하고 과적합되기 쉽다.
- **RandomForest(랜덤 포레스트)**: 결정 트리 **여러 그루를 만들어 다수결**로 예측한다(앙상블). 한 그루보다 안정적이고 정확하다.
- **GradientBoosting(그래디언트 부스팅)**: 트리를 **순서대로 쌓되, 앞 트리가 틀린 부분을 다음 트리가 보완**하도록 학습한다. 보통 성능이 높다.
- **XGBoost**: 그래디언트 부스팅을 빠르고 강력하게 구현한 라이브러리. 실무·대회에서 많이 쓴다.

**`feature_importances_` — 특성 중요도.** 트리 모델은 학습 후 "**어떤 입력 변수(특성)가 예측에 얼마나 기여했는지**"를 0~1 값으로 알려준다(전체 합이 1). 신경망에는 없는, 트리 모델 고유의 해석 도구다.

- iris의 4개 특성은 순서대로 꽃받침 길이·꽃받침 너비·꽃잎 길이·꽃잎 너비다. 결과를 보면 **세 번째(꽃잎 길이)** 의 중요도가 대부분 모델에서 가장 높다(DecisionTree 0.92, GradientBoosting 0.82 등). 즉 붓꽃 품종 구분에는 꽃잎 길이가 결정적이라는 뜻이다.
- **왜 유용한가**: 어떤 변수가 중요한지 알면, 중요하지 않은 변수를 빼서 모델을 단순화하거나(특성 선택), 결과를 설명하는 근거로 쓸 수 있다.
- 모델마다 중요도 분포가 다르다. 한 그루(DecisionTree)는 한 특성에 쏠리는 반면, 여러 트리를 쓰는 모델은 중요도가 여러 특성에 더 고르게 퍼진다.

## 4. m01_feature_importances02 — 회귀 데이터로

같은 네 모델의 **회귀 버전**으로 diabetes(당뇨 진행도) 데이터를 예측한다. 분류가 아니라 연속적인 수치를 맞추는 문제다.

```python
from sklearn.datasets import load_diabetes
from sklearn.tree import DecisionTreeRegressor
from sklearn.ensemble import RandomForestRegressor, GradientBoostingRegressor
from xgboost import XGBRegressor

x, y = load_diabetes(return_X_y=True)   # 특성 10개, 타깃은 연속 수치
x_train, x_test, y_train, y_test = train_test_split(
    x, y, train_size=0.8, random_state=123,
    # stratify=y   # 회귀(연속형 타깃)에는 stratify 사용 불가 → 삭제
)
# ... model.score() 는 회귀라 r2 로 나옴
```

- **분류 모델은 `Classifier`, 회귀 모델은 `Regressor`** 로 짝이 있다(DecisionTreeClassifier ↔ DecisionTreeRegressor 등). 문제 종류에 맞는 쪽을 쓴다.
- **회귀는 `stratify`를 쓸 수 없다.** `stratify`는 분류의 클래스 비율을 train/test에 똑같이 맞추는 옵션인데, 회귀의 타깃은 연속값이라 "클래스 비율"이라는 개념이 없어 삭제한다. (이전에 배운 내용의 복습.)
- **평가지표도 달라진다**: 분류는 정확도(acc), 회귀는 R². `model.score()`가 모델 종류에 맞는 지표를 돌려준다.
- 특성 중요도(`feature_importances_`)는 분류·회귀 모두 똑같이 나온다. diabetes에서는 세 번째·아홉 번째 특성의 중요도가 높게 나온다(실측).

## 5. m01_feature_importances03 — F score vs Gain score (XGBoost)

XGBoost에서 특성 중요도를 **두 가지 다른 기준**으로 볼 수 있다.

```python
model = XGBClassifier(random_state=123)
model.fit(x_train, y_train)

print("F Score : ", model.feature_importances_)   # 기본값 = 빈도(weight)
# F Score : 빈도수

gain_score = model.get_booster().get_score(importance_type='gain')
print("Gain Score : ", gain_score)
# Gain Score : 손실함수의 개선 점수. 높으면 개선 많이 된 것
```

- **F score(weight, 빈도)**: 그 특성이 트리에서 **분기 조건으로 몇 번 쓰였는지**(사용 횟수)를 센다. `feature_importances_`의 기본값이다. 자주 쓰였다고 해서 꼭 성능에 크게 기여한 것은 아니다.
- **Gain score(이득)**: 그 특성으로 분기했을 때 **손실(오차)이 얼마나 줄었는지**의 평균이다. 값이 클수록 그 특성이 성능 향상에 크게 기여했다는 뜻으로, "질적인 중요도"에 더 가깝다. `get_booster().get_score(importance_type='gain')`로 얻는다.
- 두 값은 다를 수 있다. **자주 쓰였지만(F score 높음) 이득은 작을 수도**, 가끔 쓰였지만 쓸 때마다 큰 이득을 줄 수도 있다. iris 결과에서 f2(꽃잎 길이)는 F score·Gain 모두 압도적으로 높아, 이 특성이 양적으로도 질적으로도 가장 중요함을 보여준다.
- `get_score`의 결과는 `{'f0': ..., 'f2': ...}`처럼 특성 이름(f + 번호)과 점수의 딕셔너리로 나온다.

## 6. m01_feature_importances04 — 특성 중요도 그래프

XGBoost가 제공하는 `plot_importance`로 특성 중요도를 막대그래프로 그린다.

```python
import matplotlib.pyplot as plt
from xgboost import plot_importance

# F-score 그래프
# plot_importance(model, importance_type='weight')
# plt.title("F-Score")
# plt.show()

# Gain-score 그래프
plot_importance(model, importance_type='gain')
plt.title("Gain-Score")
plt.show()
```

- **`plot_importance(model, importance_type=...)`** 는 특성 중요도를 **막대그래프로 바로 그려준다.** 숫자 배열로 보는 것보다 어느 특성이 큰지 한눈에 들어온다.
- **`importance_type`으로 기준을 고른다**: `'weight'`(F score, 빈도) 또는 `'gain'`(이득). 같은 모델이라도 기준에 따라 막대 순위가 달라질 수 있어, 둘을 비교해 보면 특성의 "자주 쓰임"과 "실제 기여"를 함께 파악할 수 있다.

## 7. 한 줄 요약

> **병렬 결과 통합 개선**: merge 노드가 두 병렬 결과를 단순히 이어 붙이는 대신 **LLM에게 넘겨 종합**하게 하면("검색 우선 참고, 최신/기존 구분" 같은 지시 프롬프트 포함) 매끄러운 최종 답변이 된다. **머신러닝 입문**: 딥러닝과 별개로 트리 기반 모델(DecisionTree·RandomForest·GradientBoosting·XGBoost)을 새 가상환경(conda·xgboost·scikit-learn)에서 다룬다. 트리 모델은 **`feature_importances_`로 어떤 입력 변수가 중요했는지**(합 1) 알려주며(신경망엔 없는 해석 도구), 분류는 Classifier·acc, 회귀는 Regressor·R²로 짝지어 쓰고 회귀엔 stratify를 쓰지 않는다. XGBoost의 중요도는 **F score(분기에 쓰인 빈도)** 와 **Gain score(분기로 줄인 손실=실제 기여)** 두 기준이 있고, `plot_importance(importance_type=...)`로 막대그래프로 시각화한다.
