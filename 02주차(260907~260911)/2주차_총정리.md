## 1. 훈련 과정 제어와 모니터링

### verbose — 출력량 조절
`model.fit`에서 훈련 과정을 터미널에 얼마나 출력할지 정한다(사전적 의미 "말이 많은").
- **0**: 침묵(출력 없음) · **1**: 전부 출력(프로그래스바, fit 기본값) · **2**: 프로그래스바 없이 epoch당 한 줄 · **3(및 그 외)**: Epoch 번호만.
- 출력을 끄면 그만큼 빨라지지만 진행을 볼 수 없으므로 상황에 따라 선택한다.

### 학습 시간 측정 — time
```python
import time
start = time.time()
model.fit(...)
end = time.time()
print(round(end - start, 2), "초")
```
- **`time.time()`**: 현재 시각을 초 단위로 반환. 끝난 시각 − 시작 시각 = 걸린 시간.

### History — fit의 반환값
`model.fit`은 훈련 기록을 담은 **History 객체**를 반환한다.
```python
hist = model.fit(...)
print(hist.history)   # {'loss': [...], 'val_loss': [...]}
```
- **`hist.history`**: 훈련 기록을 **딕셔너리(키 + 값)** 로 담는다. `'loss'`, `'val_loss'`가 키이고, epoch별 값들의 리스트가 값이다.
- `hist.history['loss']`처럼 키로 특정 값만 꺼낸다.
- loss·val_loss를 그래프로 그려 훈련 흐름을 확인한다. `[2:]`로 앞 몇 개를 잘라내는 것은 초반 큰 loss가 y축을 눌러 관심 구간이 안 보이는 것을 막기 위함이다.

## 2. 데이터 3등분 (validation)

지금까지의 train/test 2등분은 **훈련이 끝난 뒤에만** 평가할 수 있다. 훈련 **도중에도** 성능을 점검하기 위해 데이터를 세 덩어리로 나눈다.

- **train**: 가중치 학습용.
- **val(validation)**: 훈련 중간중간 성능 점검용.
- **test**: 훈련이 끝난 뒤 최종 평가용.

훈련은 **epoch → validation → epoch → validation** 순으로 돌며, 매 epoch마다 val로 점검한 손실이 **val_loss**다. val_loss는 상태를 지켜볼 뿐 가중치 갱신에는 직접 관여하지 않는다.

### val과 test의 차이
둘 다 훈련(fit)에는 쓰이지 않지만 보는 시점·목적이 다르다.

| 구분 | val (검증) | test (평가) |
|---|---|---|
| 언제 보나 | 훈련 중 매 epoch마다 | 훈련이 끝난 뒤 한 번 |
| 목적 | 훈련 과정 감시(과적합 확인, EarlyStopping) | 최종 성적 매기기 |
| 튜닝 영향 | 준다(val 보고 멈추거나 조정) | 안 준다(건드리지 않음) |

- test를 훈련 중 점검에 쓰면 그 데이터에 맞춰 튜닝하게 되어 최종 평가가 오염된다. 그래서 감시 전용인 val을 따로 둔다.

### 왜 훈련 중 점검이 필요한가
- 과적합이 언제 시작되는지 **실시간으로 감시**해, 적절한 시점에 멈추기 위함이다.
- 핵심은 "사람이 눈으로 보려고"가 아니라 **"코드가 자동으로 판단하게 하려고"** val을 만드는 것이다. val_loss라는 숫자가 매 epoch 생겨야, 뒤의 EarlyStopping이 그 숫자를 읽고 자동으로 멈출 수 있다. 즉 val은 자동화의 재료다.

### val을 만드는 방법
| 방법 | 방식 |
|---|---|
| `validation_data=(x_val, y_val)` | 검증용 데이터를 직접 지정 |
| 슬라이싱 | `x[:8]`, `x[8:12]`, `x[12:]`로 8/4/4 |
| `train_test_split` 두 번 | 전체를 나눈 뒤, 나머지를 다시 val/test로 |
| `validation_split=0.33` | **훈련 데이터(x_train)에서** 지정 비율(33%)을 자동으로 떼어 val로 사용 |

- `validation_split`은 항상 `model.fit`에 넣은 데이터(train)를 쪼갠다. test는 관여하지 않는다.

## 3. 과적합 자동 제어 (EarlyStopping)

### EarlyStopping — 조기 종료
val_loss가 최소값을 찍은 뒤 더 개선되지 않는데도 계속 도는 것은 비효율이며 과적합으로 이어진다. **개선이 멈추면 훈련을 자동 중단**하는 **콜백(callback)** 이다. (콜백 = 훈련 중 특정 시점에 자동 호출되는 기능.)

```python
from tensorflow.keras.callbacks import EarlyStopping
es = EarlyStopping(
    monitor='val_loss',          # 감시할 지표
    mode='min',                  # 작을수록 좋은 지표라 최소값 기준 (정확도라면 'max')
    patience=25,                 # 개선 없어도 몇 epoch까지 참을지 (숫자, 따옴표 X)
    restore_best_weights=True,   # 중단 시 가장 좋았던 지점의 가중치로 복원
)
model.fit(..., epochs=5000000, callbacks=[es])   # 콜백은 리스트로 전달
```
- `epochs`를 아주 크게 두고 종료 판단을 EarlyStopping에 맡긴다. `callbacks=[es]`는 리스트라 다른 콜백도 함께 넣을 수 있다.
- 정리: val을 나눠 val_loss를 만들고 → 그래프로 과적합을 확인하고 → EarlyStopping으로 자동 중단하는 하나의 흐름이다.

### Local Minima와 Global Minima
학습은 loss가 가장 낮은 지점을 찾아가는 과정이다.
- **Global Minima(전역 최소)**: loss가 진짜로 가장 낮은 지점(목표).
- **Local Minima(지역 최소)**: 주변보다는 낮지만 전역 최소는 아닌 지점. 여기에 갇히면 더 좋은 지점으로 못 나아갈 수 있다.

## 4. 분류 모델 개요

모든 모델은 y값의 종류에 따라 **회귀(수치 예측)** 또는 **분류(정해진 범주 예측)** 중 하나다. 분류는 라벨의 종류가 미리 정해져 있어야 하며, 범주가 2개면 **이진분류**, 3개 이상이면 **다중분류**다.

회귀 → 이진분류 → 다중분류로 갈 때 달라지는 부분을 한 표로 정리하면:

| 구분 | 회귀 | 분류(이진) | 분류(다중) |
|---|---|---|---|
| 마지막 층 activation | linear(지정 안 함) | **sigmoid** | **softmax** |
| loss | mse, mae 등 | **binary_crossentropy** | **categorical_crossentropy** |
| predict 후처리 | 없음 | **np.round** | **np.argmax** |
| OneHot Encoding | X | X | **O** |
| 마지막 층 노드 수 | 출력 개수(N) | 1개 | **y의 클래스 개수** |

## 5. 이진분류

### 구성
```python
model.add(Dense(1, activation='sigmoid'))     # 출력층: sigmoid
model.compile(loss='binary_crossentropy', optimizer='adam', metrics=['acc'])
```
- **sigmoid**: 입력을 **0~1 사이 값으로 한정**하는 활성화 함수(로지스틱 함수). S자 모양이며 입력 0에서 0.5를 지난다. 출력을 "1일 확률"처럼 해석하고 0.5 기준으로 0/1 판정한다.
- **binary_crossentropy**: 이진분류 전용 손실 함수.
- **metrics**: 훈련·평가 중 함께 볼 보조지표. 분류에서는 정확도(`'acc'` 또는 `'accuracy'`)를 넣는다. 학습에는 직접 관여하지 않으며, 넣으면 `evaluate`가 `[loss, accuracy]` 리스트를 반환한다.

### 예측 — np.round
```python
y_pred = model.predict(x_test)   # sigmoid 출력이라 0~1 확률
y_pred = np.round(y_pred)        # 0.5 기준으로 0 또는 1
acc = accuracy_score(y_test, y_pred)
```
- `accuracy_score`는 라벨(0/1)과 비교하는데 예측이 연속값이면 에러가 나므로, `np.round`로 0/1로 바꾼다.

### 분류에서 데이터 다루기
- **stratify=y**: 나눌 때 **원래 라벨 비율을 train/test 양쪽에 유지**한다. 특정 라벨이 한쪽에 몰리는 것을 막는다(특히 불균형 데이터에서 중요).
- **클래스 개수 세기**: `np.unique(y, return_counts=True)` 또는 pandas `value_counts()`.
- 내장 데이터는 딕셔너리라 `datasets.data`와 `datasets["data"]` 둘 다 접근 가능. `datasets.DESCR`(설명), `feature_names`(컬럼명), `type()`(자료형 확인).

## 6. 다중분류

### 원-핫 인코딩(OneHot Encoding)
라벨 0, 1, 2는 크기·순서가 아니라 **대등한 범주**다(2가 1의 두 배가 아님). 숫자 그대로 두면 모델이 크기로 오해하므로, **위치(자리)로 표현**한다.
```
0 → [1,0,0]   1 → [0,1,0]   2 → [0,0,1]
```
- y의 형태가 벡터 `(n,)`에서 행렬 `(n, 클래스수)`로 바뀐다. (어떤 범주가 맞는지 고르는 것은 softmax·argmax가 한다.)

**원-핫 3가지 방법**
| 방법 | 코드 | 주의점 |
|---|---|---|
| TensorFlow | `to_categorical(y)` | 0번 컬럼부터 시작이 기본. 라벨이 1부터면(covtype 1~7) 쓰지 않는 0열이 생겨 열이 하나 많아짐 |
| pandas | `pd.get_dummies(y, dtype=int)` | dtype=int를 안 주면 True/False로 나옴 |
| sklearn | `OneHotEncoder(sparse_output=False)` | 입력이 2차원이어야 함 → `y.reshape(-1,1)` 필요. `-1`은 "그 자리 크기 자동 계산" |

- **원-핫은 train_test_split보다 먼저** 한다: 한 번만 인코딩하면 되고(나눈 뒤엔 train·test를 각각 두 번), 전체를 먼저 인코딩해야 클래스 누락으로 열 구성이 어긋나는 일이 없다.

### 구성과 예측
```python
model.add(Dense(3, activation='softmax'))     # 노드 수 = 클래스 개수
model.compile(loss='categorical_crossentropy', optimizer='adam', metrics=['acc'])
...
y_predict = np.argmax(model.predict(x_test), axis=1)  # 확률 → 위치
y_test    = np.argmax(y_test, axis=1)                 # 원-핫도 위치로 (양쪽 다!)
```
- **softmax**: 출력들을 **합이 정확히 1인 확률 분포**로 만든다. 실제 수식은 각 값에 e의 지수를 취해 나눈다: e^(xᵢ)/Σe^(xⱼ). 지수를 쓰는 이유는 음수를 막고(e^x는 항상 양수), 값의 차이를 벌리기 위함이다.
- **categorical_crossentropy**: 다중분류 전용 손실 함수. loss는 softmax 확률값으로 계산되며(argmax 이전), argmax는 최종 예측 클래스를 뽑을 때만 쓴다.
- **np.argmax(axis=1)**: 각 행에서 **가장 큰 값의 위치(인덱스)** 를 반환. 예측과 정답 **둘 다** 위치로 되돌려야 형태가 맞아 비교된다. (이진분류의 np.round에 대응.)

## 7. 모델 구조 이해

### model.summary()와 파라미터 계산
**파라미터 = 학습으로 값이 바뀌는 개별 숫자.** `y = wx + b`의 w와 b는 파라미터이고, x(입력)는 고정이라 제외된다.
- 한 Dense 층 파라미터 수 = **(입력 수 × 출력 노드 수) + 출력 노드 수** ( = w의 개수 + b의 개수. bias 포함).
- 예: `Dense(3, input_dim=1)` → (1×3)+3 = 6.
- 참고: 실제 행렬 계산은 데이터 X`(샘플, 피처)`와 W`(피처, 노드)`를 곱해야 차원이 맞아 `y = XW + b` 형태가 된다.

### input_dim과 input_shape
- `input_dim=4`와 `input_shape=(4,)`는 같다.
- **input_shape는 원본 shape에서 첫 차원(샘플 수 n)을 뺀 나머지**를 튜플로 적는다: `(n,4)→(4,)`, `(n,100,3)→(100,3)`.
- input_dim은 1차원 입력에만, input_shape는 다차원 입력(이미지 등)에도 쓸 수 있어 더 일반적이다.

## 8. 데이터 스케일링

### 왜 하나
값이 너무 크거나 컬럼마다 범위가 제각각이면 학습에 불리하다. 그래서 **모든 데이터를 비슷한 범위로 줄인다.** 스케일러는 **컬럼(피처)별로** 적용된다.

### fit과 transform
```python
scaler.fit(x_train)              # 기준값(min·max 등)을 계산·저장만 (데이터 안 바꿈)
x_train = scaler.transform(x_train)   # 그 기준으로 실제 변환
x_test  = scaler.transform(x_test)    # test도 같은(train의) 기준으로 변환
# scaler.fit_transform(x_train) 은 fit+transform 한 줄 단축
```
- **fit = 자(변환 규칙)를 만든다(train만). transform = 그 자로 잰다(train·test 둘 다).**
- x_test도 transform해야 하는 이유: train이 0~1로 줄었는데 test만 원본(예: 5000)으로 두면, 0~1로 학습한 모델이 큰 값을 못 읽어 예측이 망가진다. (cm로 학습했으면 예측도 cm로 넣어야 함.)

### 왜 train 기준인가 (정보 누수 방지)
- test는 **"아직 보지 못한 미래 데이터"** 로 취급해야 한다. 전체(train+test)에 fit하면 test의 통계가 스케일러에 반영되어 **정보 누수**가 된다. 그래서 스케일러는 **train에만 fit**한다.
- 그 결과 test 변환값이 0~1(또는 각 스케일러 범위)을 살짝 벗어날 수 있는데(예: `-0.0003 ~ 1.016`), 이는 오류가 아니라 정상이다. (분리 후 train에만 fit하는 것이 올바른 방식이고, 분리 전 전체에 fit하는 것은 잘못된 방식이다.)

### 스케일러 4종
| 스케일러 | 기준값 | 식 | 결과 범위 | 특징 |
|---|---|---|---|---|
| MinMaxScaler | 최소·최대 | (x−min)/(max−min) | 0 ~ 1 | 이상치에 약함 |
| StandardScaler | 평균·표준편차 | (x−평균)/표준편차 | 제한 없음(평균 0, 표준편차 1, 대부분 −3~3) | 0 중심 표준화 |
| MaxAbsScaler | 최대 절대값 | x / \|max\| | −1 ~ 1 | 부호·0 유지 |
| RobustScaler | 중앙값·IQR | (x−중앙값)/IQR | 제한 없음 | 이상치에 강함 |

- **StandardScaler**: 평균을 0으로 이동시키고 표준편차로 퍼짐을 1로 맞춘다. 범위를 가두지 않아 음수도 나온다.
- **MaxAbsScaler**: 최대 절대값으로 나눠 −1~1로. 부호와 0을 유지.
- **RobustScaler**: 평균·표준편차 대신 **중앙값**과 **IQR**(데이터를 4등분했을 때 가운데 50% 구간 Q1~Q3의 폭)을 쓴다. 이 둘은 양 끝 극단값에 거의 영향받지 않아 이상치가 많은 데이터에 강하다. (사분위수 Q1=25%, Q2=50%=중앙값, Q3=75% 지점.)
- 어느 스케일러가 좋은지는 정해진 규칙이 없어 데이터마다 돌려서 성능이 잘 나오는 것을 선택한다. 스케일링이 항상 성능을 올리는 것도 아니다(데이터에 따라 좋아짐/비슷함/나빠짐).

## 9. 모델 save / load

```python
model.save(path + '이름.keras')                       # 저장
from tensorflow.keras.models import load_model
model = load_model(path + '이름.keras')               # 불러오기
```
- `model.save`는 저장하는 **그 순간의** 모델(구조 + 가중치 + 컴파일 정보)을 하나의 `.keras` 파일로 저장한다. 따라서 **저장 시점**이 저장되는 가중치를 결정한다.
- **모델 구성 직후 저장** → 구조 + **훈련 안 된 초기(랜덤) 가중치**. 불러오면 다시 훈련해야 한다.
- **훈련(fit) 후 저장** → 구조 + **학습된 가중치**. 불러오면 학습 결과를 그대로 쓴다.
- 정리: 구조만 재사용하려면 구성 직후 저장, 학습 결과까지 재사용하려면 훈련 후 저장.

## 10. 2주차 핵심 키워드 총괄

| 키워드 | 한 줄 정의 |
|---|---|
| verbose | 훈련 출력량 조절(0 침묵 ~ 3 epoch만) |
| validation | 훈련 중 점검용 데이터(3등분: train/val/test) |
| validation_split | 훈련 데이터에서 자동으로 val을 떼는 비율 |
| History | fit의 반환값. hist.history는 loss·val_loss 딕셔너리 |
| EarlyStopping | val_loss 개선 없으면 자동 중단하는 콜백 |
| callback | 훈련 중 특정 시점에 자동 호출되는 기능 |
| sigmoid | 이진분류 출력층. 0~1 확률로 한정 |
| softmax | 다중분류 출력층. 합이 1인 확률 분포 |
| binary/categorical_crossentropy | 이진/다중분류 전용 손실 함수 |
| OneHot Encoding | 라벨을 위치 벡터로 변환(다중분류) |
| np.round / np.argmax | 이진(0.5 기준)/다중(최대 위치) 예측 판정 |
| stratify | 라벨 비율 유지하며 분할 |
| metrics | 함께 볼 보조지표(분류는 accuracy) |
| summary / 파라미터 | (입력×출력)+출력, bias 포함 |
| input_shape | 첫 차원(샘플) 뺀 입력 형태 |
| fit / transform | 스케일러 기준 만들기(train) / 그 기준으로 변환(양쪽) |
| MinMax/Standard/MaxAbs/Robust | 0~1 / 평균0표준화 / −1~1 / 이상치에 강함 |
| model.save / load_model | 모델 저장·복원(저장 시점이 가중치를 결정) |
