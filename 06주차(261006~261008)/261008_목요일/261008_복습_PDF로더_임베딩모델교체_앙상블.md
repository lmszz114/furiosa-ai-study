## 1. PDF 문서 불러오기 — PyPDFLoader (rag19)

지난 시간 txt(TextLoader)에 이어, 이번엔 **PDF**(논문)를 RAG 소스로 쓴다. 논문은 arxiv.org 등에서 받는다.
```bash
activate langchain
pip install pypdf      # PDF 로더용 (설치 필요)
```
```python
from langchain_community.document_loaders import PyPDFLoader

pdf_loader = PyPDFLoader(path + "Attention_is_all_you_need.pdf")
pdf_docs = pdf_loader.load()

print(type(pdf_docs))   # <class 'list'>
print(len(pdf_docs))    # 15  ← PDF 페이지 수만큼 document 생성
```
- **`PyPDFLoader(파일).load()`**: PDF를 **페이지 단위로** 불러온다. 15페이지면 document 15개 리스트.
- **`load()`는 리스트를 돌려준다**: 그래서 `pdf_docs.load_and_split(...)`은 에러(리스트엔 그 메서드 없음). **`Text_splitter.split_documents(pdf_docs)`** 로 청킹해야 한다.

## 2. PDF 챗봇 — 전체 RAG 파이프라인 (rag19_2)

PDF를 넣어 지난 시간의 RAG 흐름을 그대로 완성한다. (VectorDB는 FAISS 사용.)
```python
### ① 불러오기
pdf_docs = PyPDFLoader(path + "Attention_is_all_you_need.pdf").load()   # 15페이지

### ② 청킹
split_pdf_docs = Text_splitter.split_documents(pdf_docs)   # 15페이지 → 205 청크

### ③ 임베딩
embeddings = OpenAIEmbeddings(model="text-embedding-3-small", api_key=..., base_url=...)

### ④ FAISS 저장/불러오기
# db = FAISS.from_documents(split_pdf_docs, embeddings); db.save_local(...)  # 저장 1회 후 주석
db = FAISS.load_local(DB_PATH, index_name="faiss_index19", embeddings=embeddings,
                      allow_dangerous_deserialization=True)

### ⑤ 검색기 + ⑥ RAG 체인 + Gradio
retriever = db.as_retriever(search_kwargs={"k":2})
docu_chain = create_stuff_documents_chain(model, prompt)
rag_chain  = create_retrieval_chain(retriever, docu_chain)

demo = gr.ChatInterface(fn=answer_invoke, title='Test Chat Bot')
demo.launch()
```
- **흐름은 txt 때와 동일**: 불러오기 → 청킹 → 임베딩 → VectorDB → retriever → RAG 체인 → Gradio. **소스만 PDF로 바뀐 것.**
- **저장은 1회만**: `from_documents`+`save_local`로 한 번 저장한 뒤 **주석 처리**하고, 이후엔 `load_local`로 불러 쓴다(매번 재임베딩하면 느리고 비용↑).
- 결과: Attention 논문(15페이지)을 205개 청크로 쪼개, 논문 내용을 묻는 챗봇이 된다.

## 3. 임베딩 모델 교체 — OpenAI(API) ↔ HuggingFace(로컬) (rag20)

임베딩을 **OpenAI API** 대신 **HuggingFace 로컬 모델**로 바꾸는 실습.
```python
from langchain_huggingface.embeddings import HuggingFaceEmbeddings

# bge-m3
embeddings = HuggingFaceEmbeddings(
    model_name="BAAI/bge-m3",
    model_kwargs={"device": "cpu"},   # GPU 있으면 "cuda"
)

# qwen3
embeddings = HuggingFaceEmbeddings(
    model_name="Qwen/Qwen3-Embedding-0.6B",
    model_kwargs={"device": "cpu"},
)

vector = embeddings.embed_query("삼성전자의 창업주는 누구인가요?")
print(len(vector))   # 1024 (bge-m3, qwen3 둘 다 1024차원)
```

### OpenAI vs HuggingFace 임베딩
| | OpenAIEmbeddings | HuggingFaceEmbeddings |
|---|---|---|
| 실행 | **API**(서버 호출, 키·네트워크 필요) | **로컬**(내 PC에서 모델 다운로드·실행) |
| 비용 | 사용량 과금 | 무료(내 자원 사용) |
| 예시 모델 | text-embedding-3-small(1536)/large(3072) | BAAI/bge-m3(1024), Qwen/Qwen3-Embedding-0.6B(1024) |
| 사용법 | `OpenAIEmbeddings(model=, api_key=, base_url=)` | `HuggingFaceEmbeddings(model_name=, model_kwargs={"device":...})` |

- **`HuggingFaceEmbeddings`**: `langchain_huggingface` 패키지 필요(내부적으로 모델을 다운로드해 로컬에서 돌림). `device`로 cpu/gpu 선택.
- **처음 실행 시 모델이 자동 다운로드**된다(이후엔 캐시 사용, `local_files_only`로 오프라인 강제 가능).

### ⚠️ 임베딩을 바꾸면 VectorDB를 새로 만들어야 한다
- OpenAI(1536차원)로 저장한 DB를 **bge-m3(1024차원)로는 못 읽는다**(차원이 달라 검색 불가).
- **임베딩 모델을 바꾸면 그 임베딩으로 문서를 다시 임베딩해 DB를 재저장**해야 한다. (저장 때와 불러올 때 임베딩이 같아야 함.)

### rag20_embedding4_ChatBot — 교체한 임베딩으로 챗봇
- bge-m3(로컬 임베딩) + FAISS + RAG 체인 + Gradio. 임베딩만 바꿨을 뿐 **나머지 파이프라인은 동일**. (단, 위 주의대로 DB는 bge-m3로 새로 저장한 것을 써야 함.)

## 4. (keras) 앙상블 모델 — 여러 입력/출력 합치기 (keras69)

**앙상블**: 여러 개의 모델(입력)을 **합쳐(Concatenate)** 하나로 만든 모델. 입력이 여러 종류일 때 쓴다.

### 기본 구조 (함수형 API)
```python
# 입력마다 별도 모델 (input_shape는 각 데이터 피처 수)
input1 = Input(shape=(2,)); ... ; output1 = Dense(5)(...)   # 모델1 (피처 2)
input2 = Input(shape=(3,)); ... ; output2 = Dense(3)(...)   # 모델2 (피처 3)
input3 = Input(shape=(4,)); ... ; output3 = Dense(3)(...)   # 모델3 (피처 4)

# 합치기
from tensorflow.keras.layers import Concatenate
merge1 = Concatenate()([output1, output2, output3])   # 세 모델 출력을 이어붙임
merge2 = Dense(10)(merge1)
last   = Dense(1)(merge2)

model = Model(inputs=[input1, input2, input3], outputs=last)   # 입력 리스트
model.fit([x1_train, x2_train, x3_train], y_train, ...)         # 입력도 리스트로
```
- **입력마다 `Input(shape=...)` 의 피처 수를 데이터에 맞춰야** 한다(x2가 3피처면 `Input(shape=(3,))` — 안 맞으면 "expected (None,2) found (None,3)" 에러).
- **합칠 땐 `Concatenate()([out1, out2, ...])`**, 모델 생성 시 **`inputs=[...]` 리스트**, 훈련도 **`[x1,x2,x3]` 리스트**로.

### 출력도 여러 개 — 분기 (keras69_ensemble3)
합친 뒤 **출력을 여러 갈래로 나눌 수 있다**(예: 화성온도 y1, 비트코인 y2 동시 예측).
```python
# 분기1
b1 = Dense(10)(merge3); b1 = Dense(10)(b1); last_output1 = Dense(1)(b1)
# 분기2
last_output2 = Dense(1)(merge3)

model = Model(inputs=[input1, input2, input3], outputs=[last_output1, last_output2])

model.fit([x1_train, x2_train, x3_train], [y1_train, y2_train], ...)   # ★ 타깃도 리스트
loss = model.evaluate([x1_test, x2_test, x3_test], [y1_test, y2_test])
y1_pred, y2_pred = model.predict([x1_pred, x2_pred, x3_pred])           # ★ 출력 2개 언패킹
```
- **출력이 여러 개면 타깃(y)도 `[y1, y2]` 리스트**로. (안 묶으면 y2가 batch_size 자리로 들어가 "multiple values for batch_size" 에러.)
- **`predict`는 출력 2개를 리스트로 반환** → `y1_pred, y2_pred = model.predict(...)`로 **한 번에 풀어 받기**. (통째로 한 변수에 담고 `[-1]` 하면 두 번째 출력을 집어 엉뚱한 값이 나옴.)
- 세 파일 비교: **ensemble1**(입력 2·출력 1) → **ensemble2**(입력 3·출력 1) → **ensemble3**(입력 3·출력 2, 분기).

### 앙상블에서 자주 난 에러 (정리)
| 에러 | 원인 | 해결 |
|---|---|---|
| stratify ValueError | 회귀 y에 `stratify=y`(분류용) | stratify 삭제 |
| expected (None,2) found (None,3) | Input 피처 수가 데이터와 불일치 | 각 `Input(shape=(피처수,))` 맞추기 |
| multiple values for batch_size | 출력 여러 개인데 y를 리스트로 안 묶음 | `[y1_train, y2_train]`로 |
| predict 결과 엉뚱 | 출력 2개 리스트를 한 변수에 담고 `[-1]` | `y1,y2 = model.predict(...)` 언패킹 |

## 6. 오늘 한 줄 요약

> **PDF RAG**: `PyPDFLoader().load()`는 PDF를 페이지 단위 리스트로 불러오고(`load()` 결과는 리스트라 `split_documents`로 청킹), 이후 임베딩→FAISS→retriever→RAG 체인→Gradio 흐름은 txt 때와 동일하다(소스만 PDF).
> **임베딩 교체**: OpenAI(API·과금·1536/3072) 대신 **HuggingFace 로컬 모델**(bge-m3·qwen3, 1024차원, 무료·로컬 실행)을 `HuggingFaceEmbeddings(model_name, model_kwargs)`로 쓴다. 단, **임베딩을 바꾸면 차원이 달라져 VectorDB를 그 임베딩으로 새로 저장**해야 한다.
> **앙상블**: 여러 입력 모델을 **`Concatenate`로 합쳐** `Model(inputs=[...])`로 만들고, 입력은 `[x1,x2,x3]` 리스트로 넣는다. 출력을 여러 갈래로 **분기**하면 타깃도 `[y1,y2]` 리스트, `predict`는 `y1,y2 = model.predict(...)`로 풀어 받는다. (각 `Input` 피처 수를 데이터에 맞추고, 회귀엔 stratify를 쓰지 않는다.)
