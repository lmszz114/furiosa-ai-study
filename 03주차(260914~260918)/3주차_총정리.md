## 1. 모델 저장·복원

### 저장 3방식
| 방식 | 저장 대상 | 확장자 | 불러올 때 |
|---|---|---|---|
| `model.save()` | 전체 모델(구조 + 가중치) | .keras | `load_model`만으로 완성 |
| `model.save_weights()` | 가중치만 | .weights.h5 | 모델 구조를 코드에 먼저 만들어야 함 |
| `ModelCheckpoint` | 훈련 중 **최고 지점**의 전체 모델(자동) | .keras | `load_model`만으로 완성 |

- 저장 **시점**이 담기는 가중치를 결정한다: 구성 직후 저장 → 초기(랜덤) 가중치 / 훈련 후 저장 → 학습된 가중치.

### ModelCheckpoint (MCP)
```python
from tensorflow.keras.callbacks import ModelCheckpoint
mcp = ModelCheckpoint(monitor='val_loss', mode='auto',
                      save_best_only=True,              # 개선될 때만(최고 지점만) 저장
                      filepath=path + 'best.keras', verbose=1)
model.fit(..., callbacks=[es, mcp])
```
- 훈련 도중 val_loss가 가장 좋은 지점의 **전체 모델**을 파일로 자동 저장한다.
- 파일명에 날짜·epoch·val_loss를 넣어(`{epoch:04d}-{val_loss:.4f}.keras`, `datetime.strftime`) 어느 시점·성능의 모델인지 구분할 수 있다.

### restore_best_weights vs ModelCheckpoint (헷갈리기 쉬움)
| | restore_best_weights(EarlyStopping) | ModelCheckpoint |
|---|---|---|
| 하는 일 | **메모리**상 모델을 최고 지점으로 복원 | 최고 지점을 **파일**로 저장 |
| 언제 | 훈련 끝난 후 | 훈련 도중(실시간) |
| 용도 | 훈련 직후 바로 하는 평가·예측용 | 나중에 다시 불러 쓸 백업용 |

- 둘은 **독립적**이며(서로 정보를 주고받지 않음) 역할이 달라 함께 쓴다. mcp가 파일을 저장해도, 훈련 직후 평가에 쓰는 것은 "메모리의 model"이므로 그 메모리를 최고 지점으로 만드는 restore가 따로 필요하다.

## 2. 과적합 방지 — Dropout

```python
from tensorflow.keras.layers import Dropout
model.add(Dense(40, activation='relu'))
model.add(Dropout(0.2))     # 바로 앞 층 노드의 20%를 무작위로 제외
```
- **`Dropout(0.2)`**: 앞 층 노드를 **각각 20% 확률로 독립적으로** 끈다(평균적으로 20%가 꺼지며, 정확히 20개가 아니다). 매 epoch마다 꺼지는 노드가 랜덤하게 바뀐다.
- 효과: 특정 노드에 과하게 의존하는 것을 막아 **과적합을 줄인다.**
- **훈련(fit) 중에만 적용된다.** 평가·예측 시에는 모든 노드를 사용한다.

## 3. 함수형(Functional) 모델

```python
from tensorflow.keras.models import Model
from tensorflow.keras.layers import Input
input1  = Input(shape=(8,))
dense1  = Dense(40, activation='relu')(input1)   # 층을 함수처럼 호출해 앞 층에 연결
output1 = Dense(1)(dense1)
model   = Model(inputs=input1, outputs=output1)
```
- Sequential은 층을 일렬로만 쌓는다. 다중 입출력·분기 같은 복잡한 구조(예: 트랜스포머)는 함수형으로 만든다.
- 같은 구조라면 Sequential과 함수형의 **파라미터 수·성능은 동일**하다(표현 방식만 다름).

## 4. GPU 실습환경

### 버전 조합 (정확히 맞춰야 동작)
| 구성요소 | 버전 |
|---|---|
| Python | 3.10.x |
| TensorFlow(GPU) | 2.9.3 (`tensorflow-gpu`) |
| CUDA | 11.2.2 |
| cuDNN | 8.1.1 (for CUDA 11.2) |
| numpy | 1.26.4 / scikit-learn 1.7.2 |

- TensorFlow는 **2.10 이하에서만 윈도우 네이티브 GPU를 지원**하므로 구버전(2.9.3) + 그에 맞는 CUDA 11.2 / cuDNN 8.1을 쓴다.
- 설치 순서: NVIDIA 드라이버 → CUDA 11.2.2(custom 설치, VS Integration·Sample·Doc·Display Driver·PhysX 끄기) → cuDNN 8.1.1(파일을 CUDA 폴더에 복사) → 가상환경 `tf29x-gpu`(py3.10) + `tensorflow-gpu==2.9.3` → numpy 충돌 시 1.26.4로.
- 확인: cmd에서 `nvidia-smi`(드라이버), `nvcc -V`(CUDA). 코드에서 `tf.config.experimental.list_physical_devices('GPU')`로 GPU 인식 확인(비어 있으면 GPU 없음).

### GPU가 빠른 경우 / CPU가 빠른 경우
- **GPU는 한 번의 계산 덩어리가 무거울 때(이미지·큰 모델) 유리**하다. 표(정형) 데이터에 얕은 Dense 모델은 계산이 가벼워 GPU 병렬 이점이 덜 살고, 데이터를 GPU로 옮기는 비용까지 겹쳐 CPU가 빠를 수 있다.
- 실측: MNIST+CNN에서 CPU 536초 vs GPU 138초로 GPU가 확실히 빨랐다.

## 5. CNN 이론

### 모델별 입력 차원
- **DNN**(Deep Neural Network, 심층 신경망) · **RNN**(Recurrent Neural Network, 순환 신경망) · **CNN**(Convolutional Neural Network, 합성곱 신경망). 공통 NN = 신경망.

| 모델 | 입력 차원 | 예 |
|---|---|---|
| DNN | 2차원 (샘플, 피처) | csv 표 데이터 |
| RNN | 3차원 (샘플, 시점, 피처) | 순차 데이터 |
| CNN | 4차원 (샘플, 높이, 너비, 채널) | 이미지 |

### 이미지 수치화와 합성곱(convolution)
- 이미지는 **픽셀 단위로 잘라 각 픽셀 값(밝기 0~255)을 수치**로 만들어 4차원으로 넣는다.
- CNN은 `y = wx + b`에 **커널(kernel, = 가중치)** 을 적용한다. 이미지를 커널 크기만큼 조각내어, 각 조각과 커널을 **원소별로 곱해 더한다(+bias)**. 커널을 한 칸씩 옮기며 전체를 훑는다.

### 합성곱 계산 예시
입력(4×4)에 커널(2×2, 전부 1), bias 0:

입력:
| 0 | 0 | 0 | 0 |
|---|---|---|---|
| 0 | 1 | 2 | 0 |
| 0 | 2 | 3 | 0 |
| 0 | 0 | 0 | 0 |

→ 출력(3×3): 각 위치에서 2×2 영역과 커널을 곱해 더함 (예: 가운데 = 1+2+2+3 = 8)
| 1 | 3 | 2 |
|---|---|---|
| 3 | 8 | 5 |
| 2 | 5 | 3 |

- 출력 크기 = **입력 − 커널 + 1** (4−2+1 = 3).

## 6. CNN 모델 구조

### Conv2D와 input_shape
```python
model.add(Conv2D(64, (3,3), input_shape=(28,28,1)))   # 필터 64, 커널 3×3
```
- **`Conv2D(필터 수, (커널 높이, 커널 너비))`**. `input_shape=(높이, 너비, 채널)` — 행(샘플 수)은 제외. 채널 1=흑백, 3=컬러.
- 출력 노드 수를 4차원에서는 **filters**, 2차원(Dense)에서는 **units**라고 부른다.

### Conv2D 파라미터 계산
$$ \text{파라미터} = \text{필터 수} \times (\text{커널 높이} \times \text{커널 너비} \times \text{입력 채널 수} + 1) $$
- **입력 채널 수 = 바로 앞 층의 필터 수.**
- 예: `Conv2D(4,(2,2),input_shape=(5,5,1))` → 4×(2×2×1+1)=**20**, 다음 `Conv2D(3,(2,2))` → 3×(2×2×4+1)=**51**.

### Flatten — 4차원을 2차원으로
Conv2D 출력은 4차원(예 `(N,20,20,16)`)인데 Dense는 2차원을 받는다. **Flatten**으로 펼쳐(20×20×16=6400) `(N,6400)`으로 만든 뒤 Dense로 연결한다.

- **CNN 구조 요약: Conv2D(특징 추출) → (크기 조절) → Flatten/GAP(펼치기·압축) → Dense(분류) → softmax/sigmoid.**

## 7. 이미지 데이터 전처리

```python
# ① 4차원 reshape (Conv2D 입력 형태로)
x_train = x_train.reshape(-1, 28, 28, 1)     # (60000,28,28) → (60000,28,28,1)

# ② 스케일링 (픽셀은 0~255 고정이라 직접 나눔)
x_train = x_train / 255.                     # 0~1 (MinMax와 같음)
# x_train = (x_train - 127.5) / 127.5        # -1~1 (MaxAbs와 같음)

# ③ y 원-핫 (다중분류일 때)
y_train = OneHotEncoder(sparse_output=False).fit_transform(y_train.reshape(-1,1))
```
- MNIST는 흑백이라 채널이 생략된 `(60000,28,28)`이므로 reshape로 `,1`을 붙인다.
- 이미지 스케일링은 스케일러 객체 대신 255로 직접 나누는 방식을 통상 쓴다.

## 8. 이미지 크기 조절 — padding · stride · MaxPooling · GAP

Conv2D를 지나면 이미지가 계속 작아진다(외곽 정보 손실). 크기를 조절하는 도구들:

- **padding='same'**: 외곽을 0으로 채워 출력 크기를 입력과 같게 유지. (기본값 `'valid'`는 패딩 없음 → 줄어듦.)
- **strides**: 커널 이동 보폭(기본 1). 키우면 크기가 더 줄고 계산이 빨라지지만 정보를 덜 봐 정확도가 떨어질 수 있다(정확도↔속도 트레이드오프).
- **MaxPooling2D**: 영역(기본 2×2)에서 최댓값만 남겨 크기를 반으로 줄인다. **학습 파라미터가 0**이라 연산 부담 없이 크기를 줄인다.
- **GlobalAveragePooling2D (GAP)**: Flatten의 대안. 각 채널의 공간값을 **평균 하나**로 압축한다(`(N,20,20,16)`→`(N,16)`). Flatten이 6400개를 만드는 자리에서 16개만 만들어 **파라미터가 급감**하고, 과적합이 줄고 속도가 빨라진다.
- (참고: Dropout과 MaxPooling 순서는 통상 Conv2D→Dropout→MaxPooling이지만, 반대가 더 나은 경우도 있어 실험으로 정한다.)

## 9. 폴더 이미지 다루기 (ImageDataGenerator)

내장 데이터가 아니라 **내 폴더의 이미지 파일**을 읽어 수치화한다.

### ImageDataGenerator — 전처리·증강
```python
train_datagen = ImageDataGenerator(
    rescale=1./255,
    horizontal_flip=True, vertical_flip=True,       # 뒤집기
    width_shift_range=0.1, height_shift_range=0.1,  # 이동
    rotation_range=5, zoom_range=1.2, shear_range=0.7,  # 회전·확대·기울이기
    fill_mode='nearest',                            # 빈 공간 채우기
)
test_datagen = ImageDataGenerator(rescale=1./255)   # test는 증강 없이 스케일링만
```
- **데이터 증강(augmentation)**: 원본을 변형해 데이터 양을 늘려 과적합을 줄인다. **test에는 증강하지 않는다**(평가는 원본으로).

### flow_from_directory — 폴더에서 자동 라벨링
```python
xy_train = train_datagen.flow_from_directory(
    './_data/image/brain/train/',   # 상위 폴더까지만 주면 하위 폴더(ad/normal)로 자동 라벨링
    target_size=(150,150),          # 크기 통일
    batch_size=160, class_mode='binary', color_mode='grayscale', shuffle=True)
```
- 결과는 **DirectoryIterator**(반복자). `xy_train[0]`=첫 배치, `xy_train[0][0]`=x, `xy_train[0][1]`=y.

### npy 저장/불러오기 — 매번 수치화가 느려서
이미지 수치화는 실행마다 오래 걸리므로, 한 번 수치화한 배열을 저장해두고 재사용한다.
```python
np.save(np_path + 'x_train.npy', arr=x_train)   # 저장 (수치화 → 저장 → exit())
x_train = np.load(np_path + 'x_train.npy')       # 불러오기 (수치화 과정 없음, 빠름)
```

## 10. CNN ↔ DNN 변환

- **CNN → DNN**: 이미지를 1차원으로 펼쳐(`28×28=784`) Dense만으로 학습. **통상 이미지에서는 CNN이 DNN보다 낫다**(공간 구조 활용). 단순 이미지는 예외 가능.
- **DNN → CNN**: 표 데이터를 4차원으로 만들어 Conv2D에 넣음. 표는 공간 구조가 없어 대체로 이득이 없다(reshape 시 피처 개수를 정확히: 산탄데르 200 → `reshape(-1,200,1,1)`).

## 11. 실전 트러블슈팅

- **이진분류 세트**: 출력층 `sigmoid` / loss `binary_crossentropy` / 예측 `np.round`. (다중분류는 `softmax` / `categorical_crossentropy` / `np.argmax`.) `class_mode='binary'`면 y가 1차원이라 argmax가 아닌 round.
- **CIFAR 다운로드 실패(Timeout/404)**: 파일을 `.keras\datasets`에 넣고 압축을 풀어 사용(다운로드가 시작되면 위치·이름이 틀린 것, 안 되면 VSCode 재시작).
- **OOM(ResourceExhaustedError)**: GPU 메모리 부족. 이미지처럼 큰 데이터는 batch_size를 작게(16 등), 또는 이미지 크기·모델을 줄인다.

## 12. 3주차 핵심 키워드 총괄

| 키워드 | 한 줄 정의 |
|---|---|
| model.save / save_weights / ModelCheckpoint | 전체 저장 / 가중치만 / 훈련 중 최고점 자동 저장 |
| restore_best_weights | 메모리 모델을 최고점으로 복원(파일 저장 아님) |
| Dropout | 노드 일부 랜덤 제외로 과적합 방지(훈련 중에만) |
| 함수형 모델 | Input·Model로 복잡한 구조 설계, 성능은 동일 |
| GPU 세팅 | py3.10·tf-gpu2.9.3·CUDA11.2·cuDNN8.1 조합 |
| CNN / 합성곱 | 커널(=가중치)로 이미지 조각내 곱·합, 출력=입력−커널+1 |
| Conv2D 파라미터 | 필터수 ×(커널×커널×입력채널+1), 입력채널=앞 층 필터수 |
| Flatten / GAP | 4차원 펼치기(파라미터 폭증) / 채널 평균 압축(파라미터 급감) |
| padding / stride / MaxPooling | 크기 유지 / 보폭 / 최댓값으로 반 축소(파라미터 0) |
| ImageDataGenerator | 폴더 이미지 수치화 + 증강, flow_from_directory 자동 라벨링 |
| 데이터 증강 | 이미지 변형으로 데이터 늘려 과적합 방지(test 제외) |
| np.save / np.load | 수치화한 배열 저장·재사용(수치화 반복 방지) |
| OOM | GPU 메모리 부족 → batch/이미지 크기 줄이기 |
