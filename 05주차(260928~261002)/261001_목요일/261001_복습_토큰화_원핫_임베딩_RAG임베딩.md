# 2026.10.01 복습 — 텍스트 수치화(토큰화·원핫·패딩)와 임베딩, RAG 임베딩

> 오늘 흐름: 텍스트를 숫자로 바꾸는 토큰화 → 숫자를 "위치값"으로 바꾸는 원핫(3가지) → 길이 맞추는 패딩 → 모델에 넣기(DNN·LSTM) → 원핫의 한계 → **임베딩** 등장 → (RAG) OpenAI 임베딩으로 문장을 벡터로. 전체 주제: **"텍스트를 어떻게 숫자로 표현할 것인가"**.

---

## 1. Tokenizer — 텍스트를 숫자로 (keras60_Tokenizer1)

모델은 숫자만 다루므로, 텍스트를 먼저 숫자로 바꿔야 한다. Keras `Tokenizer`가 이 일을 한다.

```python
from tensorflow.keras.preprocessing.text import Tokenizer

text = "나는 지금 진짜 진짜 매우 매우 맛있는 김밥을 엄청 마구 마구 마구 마구 먹었다."

token = Tokenizer()          # 객체(인스턴스) 생성
token.fit_on_texts([text])   # 텍스트를 학습해 단어장 구축

print(token.word_index)
# {'마구': 1, '진짜': 2, '매우': 3, '나는': 4, ... '먹었다': 9}
print(token.word_counts)
# OrderedDict([('나는', 1), ('진짜', 2), ... ('마구', 4), ('먹었다', 1)])
```

- **`fit_on_texts`**: 텍스트에서 단어(어절)를 뽑아 **번호를 매긴다**. **많이 나온 단어일수록 작은 번호**('마구' 4번 등장 → 1번).
- **`word_index`**: 단어↔번호 대응표(단어장). **`word_counts`**: 단어별 등장 횟수.
- 어절(공백) 단위로 잘리며, **문장부호는 기본 설정(`filters`)이 자동 제거**한다("먹었다."→"먹었다").

### 숫자로 변환
```python
x = token.texts_to_sequences([text])
# [[4, 5, 2, 2, 3, 3, 6, 7, 8, 1, 1, 1, 1, 9]]   ← 리스트 안 리스트(2차원)
x = x[0]   # 안쪽 리스트만 꺼내 1차원으로
```

### 왜 여기서 끝내지 않고 원핫까지 하나 (핵심 이유)
- `texts_to_sequences`의 번호(1, 2, 3…)는 **그냥 이름표(ID)** 일 뿐, **크기·순서에 의미가 없다.**
- 예: '마구'=1, '진짜'=2라고 해서 **'마구'가 2개 있으면 '진짜'가 되는 게 아니다.** 번호는 양(value)이 아니다.
- 그런데 모델은 숫자를 "값(크기)"으로 취급하므로, ID를 그대로 넣으면 "2가 1보다 크다" 같은 가짜 의미가 생긴다.
- 이를 없애려고 **번호(값) → 위치(position)** 로 바꾸는 것이 **원핫 인코딩**이다.

## 2. 원핫 인코딩 3가지 방법 (keras60_Tokenizer1 · 2)

같은 원핫을 세 가지 도구로 만들 수 있고, 각자 입력 요구가 다르다.

| 방법 | 입력 요구 | 결과 | 비고 |
|---|---|---|---|
| `to_categorical` (tf) | 리스트/배열 OK | (N, 클래스수) | 0번 자리까지 생겨 열이 하나 더 많음 |
| `get_dummies` (pandas) | **1차원** | (N, 고유값수) | 바로 DataFrame |
| `OneHotEncoder` (sklearn) | **2차원** `(N,1)` | (N, 고유값수) | `reshape(-1,1)` 필요 |

```python
############ sklearn OneHotEncoder ############
from sklearn.preprocessing import OneHotEncoder
x = np.array(x)          # 리스트 → numpy (reshape 쓰려면 필수)
x = x.reshape(-1, 1)     # (14, 1)  2차원으로
ohe = OneHotEncoder(sparse_output=False)
x = ohe.fit_transform(x)  # (14, 9)  각 토큰이 9차원 원핫 벡터
```

- `OneHotEncoder`는 **2차원**을 요구하므로 `reshape(-1, 1)`로 바꿔야 한다(1차원 주면 에러). `.reshape`는 numpy 전용이라 리스트는 `np.array`로 먼저 변환.

### 텍스트 리스트 2개 합치기 (keras60_Tokenizer2)
문장이 여러 개면 `texts_to_sequences`가 **리스트 안 리스트**(길이 제각각)를 돌려준다. 이를 하나로 이어야 원핫할 수 있다.
```python
x = token.texts_to_sequences([text1, text2])   # [[5,6,...,10], [11,12,...,4]]
# x = x[0] + x[1]            # 파이썬 리스트 이어붙이기(결과: 리스트)
x = np.concatenate(x)        # ★ numpy 배열로 바로 이어붙임(강사 힌트)
```
- **`np.concatenate(x)`**: `x`(리스트들의 리스트) 전체를 한 번에 이어 **numpy 배열**로 만든다. `x[0]+x[1]`과 결과는 같지만, 리스트가 몇 개든 그대로 동작하고 결과가 바로 numpy라 `np.array` 변환이 불필요하다.
- 1차원끼리 이어붙이는 것이라 두 문장의 길이가 달라도(14+10=24) 문제없다.

## 3. 패딩 (pad_sequences) — 길이 맞추기 (keras61_Embedding01)

문장마다 단어 수가 달라 길이가 제각각이면 모델에 넣을 수 없다. **가장 긴 것 기준으로 빈자리를 0으로 채워** 길이를 통일한다.
```python
from tensorflow.keras.preprocessing.sequence import pad_sequences
padded_x = pad_sequences(x,
                         padding='pre',       # 앞에 0 채움 (뒤는 'post')
                         maxlen=5,            # 길이 5로 통일
                         truncating='post')   # 길이 초과 시 뒤를 자름 (기본은 앞 'pre')
# [2,3] → [0,0,0,2,3]
```
- **`padding='pre'`(앞 채움)를 기본으로 권장**: 뒤에 0을 채우면(post) 뒤로 갈수록 0이 많아 맥락이 흐려질 수 있다.
- **`maxlen`**: 통일할 길이. 넘치면 `truncating`으로 자른다('post'=뒤 자름).
- 결과 `(15, 5)` — 문장 15개, 각 길이 5.

## 4. 토큰을 모델에 넣기 — DNN → LSTM → 원핫+LSTM

영화평(docs 15개) 긍정/부정 이진분류로, 입력 표현을 바꿔가며 실험한다.

### ① raw 토큰 → DNN (keras61_Embedding01)
- `padded_x`(정수 그대로)를 DNN에 투입. `input_shape=(5,)`, 출력 `Dense(1, activation='sigmoid')`.
- **한계**: 토큰 번호를 크기로 취급해 의미를 못 배운다(1장의 이유). + 데이터 12개로 너무 적어 예측이 한쪽으로 쏠린다. **"원래 잘 안 되는" 빌드업 단계.**

### ② raw 토큰 → LSTM (keras61_Embedding02)
- `padded_x.reshape(15,5,1)`로 3차원 만들어 `LSTM(256, input_shape=(5,1))`에 투입.
- 여전히 토큰을 1개 피처(값)로 넣는 것이라 근본 한계는 같다.
- *주의*: 이 파일은 출력층이 `Dense(1)`로 **sigmoid가 빠져 있다.** 이진분류 + `binary_crossentropy`에서는 확률을 내려면 `Dense(1, activation='sigmoid')`가 맞다(03 파일에선 추가됨).

### ③ 원핫 + LSTM (keras61_Embedding03)
- 토큰을 **원핫(위치값)으로** 바꿔 LSTM에 투입. `to_categorical`로 2D→3D 원핫.
```python
padded_x = to_categorical(padded_x, num_classes=31)   # (15, 5) → (15, 5, 31)
model.add(LSTM(256, input_shape=(5, 31)))             # 피처 31
model.add(Dense(1, activation='sigmoid'))

# 예측도 똑같이 원핫 (num_classes=31 반드시 지정)
pred_pad = to_categorical(pred_pad, num_classes=31)   # (1, 5, 31)
```
- **`num_classes=31`**: 단어 30개 + 패딩 0 = 31. 예측 입력에도 **반드시 같은 31**을 줘야 열 개수가 맞는다(안 주면 그 문장 최대 토큰 기준이라 열이 모자라 터짐).
- 원핫은 "값→위치" 문제를 해결하지만, 다음 한계가 드러난다.

## 5. 원핫의 문제점 → 임베딩 등장 (keras61_Embedding03 주석)

```
# 원핫의 문제점
# 데이터가 많아질수록 필요없는 0이 많아짐 (필요한 건 1 하나인데 0이 너무 많음)
# 즉, 단어가 많아질수록 연산량이 필요 이상으로 높아짐
# 그래서 원핫을 쓰지 않고 → 임베딩을 한다
```

- 원핫 벡터는 **단어 수만큼 길어지고 그 중 1은 딱 하나, 나머지는 전부 0**(희소, sparse). 단어가 1만 개면 벡터 하나가 1만 차원인데 의미 있는 값은 1개뿐.
- **메모리·연산 낭비가 크고**, 단어끼리 전부 "똑같이 동떨어진" 관계라 **의미·유사도도 못 담는다.**
- 이 한계를 푸는 것이 **임베딩**이다. 오늘 토큰화→원핫 실습은 전부 **"왜 임베딩이 필요한가"를 체감시키는 빌드업**이었다.

## 6. ★ Embedding 층 (keras61_Embedding04)

단어 번호를 **학습되는 밀집 벡터(dense vector)** 로 바꾼다. 원핫과 달리 0 범벅이 아니라, 의미를 담은 짧은 실수 벡터다.

```python
from tensorflow.keras.layers import Embedding

model.add(Embedding(input_dim=30, output_dim=10, input_length=5))
#                   단어사전 크기,  벡터 차원,     문장 길이
model.add(SimpleRNN(10))
model.add(Dense(1))
# embedding (Embedding)   (None, 5, 10)   300      ← 30 × 10
# simple_rnn (SimpleRNN)  (None, 10)      210      ← 10×(10+10+1)
```

### 파라미터 = input_dim × output_dim
- Embedding은 크기 `(input_dim, output_dim)`짜리 **룩업 테이블(사전)**: 각 단어 번호마다 길이 `output_dim`짜리 벡터를 갖는다.
- `30 × 10 = 300`개가 전부 학습 대상(처음엔 랜덤 → 학습하며 "비슷한 단어는 비슷한 벡터"가 되도록 조정).
- **`input_length`(문장 길이)는 파라미터에 영향 없다**(표에서 몇 번 조회하든 표 크기는 그대로). Embedding엔 **bias도 없다**(그냥 꺼내오기라서).

### 인자 3가지와 작성법 (주의점)
```python
Embedding(input_dim=30, output_dim=10, input_length=5)  # 기본형
Embedding(input_dim=30, output_dim=10)                  # input_length 생략 OK (알아서 맞춤)
Embedding(30, 10)                                       # 이름 생략 — 맨 앞이 input_dim(출력 아님!)
# Embedding(30, 10, 5)  ← ✗ 세 번째 위치 인자는 input_length가 아님 (에러/무시)
```
- **맨 앞 숫자는 output이 아니라 input_dim(단어사전 크기)** 이다. Dense와 순서가 반대라 헷갈리기 쉬움.
- `input_length`는 위치 인자(세 번째)로 못 넣고, 생략하거나 키워드로 명시해야 한다.

### 주의 — input_dim은 "최대 토큰 번호 + 1"이 안전
- 이 실습의 단어장은 1~30번(+패딩 0)이라 **실제 안전한 값은 `input_dim=31`**이다. `input_dim=30`이면 **30번 토큰('구라친다')이 범위를 벗어나** 학습 시 문제가 될 수 있다. (*주의* — 강사 예제는 30으로 쓰여 있으나, 토큰 최대 번호가 input_dim 이상이면 벗어남. 안전하게는 `len(word_index)+1`.)

> keras61_Embedding04는 한 파일에 Embedding 3가지 작성법을 나열한 **문법 예시 모음**이다(세 개를 실제로 한 모델에 쌓으면 정상 동작하지 않음 — 각각 따로 보는 용도).

## 7. (RAG) OpenAI 임베딩 — 문장을 벡터로 (rag10_Embedding01 · 02)

keras Embedding이 "단어 번호→학습 벡터"라면, RAG에서는 **이미 학습된 임베딩 모델**로 **문장 전체를 의미 벡터로** 바꾼다.

```python
from langchain_openai import OpenAIEmbeddings

embeddings = OpenAIEmbeddings(
    model="text-embedding-3-large",   # 임베딩 전용 모델
    api_key=api_key, base_url=base_url,
)
vector = embeddings.embed_query("삼성전자의 창업주는 누구인가요?")
print(len(vector))   # 벡터 차원
```

- **`embed_query(문장)`**: 문장을 **고정 길이 실수 벡터**로 변환. 이 벡터가 문장의 "의미 좌표"다.
- **모델별 기본 차원**(사실):
  - `text-embedding-3-small` → **1536차원**
  - `text-embedding-3-large` → **3072차원**
  - (코드 주석의 "1536"은 small 기준 잔재 — large는 3072다.)
- **`dimensions=N`**: 차원을 줄여서 받을 수 있다(rag10_02에서 `dimensions=5`). 저장·연산을 가볍게 하려는 옵션.

### 왜 RAG에서 임베딩이 핵심인가
- 문장을 의미 벡터로 바꾸면, **벡터끼리 가까운 정도로 "의미가 비슷한 문서"를 찾을 수 있다**(검색). RAG의 retrieval(관련 문서 검색)이 바로 이 임베딩 벡터 비교로 이뤄진다.
- 즉 keras에서 배운 "단어→벡터" 개념이, RAG에선 "문장/문서→벡터"로 확장되어 **검색의 기반**이 된다.

## 9. 오늘 한 줄 요약

> 텍스트는 **토큰화**(`Tokenizer`, 단어→번호)로 숫자가 되지만, 번호는 크기 의미가 없어 **원핫**으로 "값→위치"를 바꾼다(to_categorical/get_dummies/OneHotEncoder, 입력 요구가 각기 다름). 길이는 **패딩**(`pad_sequences`, pre·maxlen·truncating)으로 통일한다.
> 원핫은 **단어가 많아질수록 0투성이(희소)라 연산 낭비 + 의미도 못 담는** 한계가 있어 → **임베딩**을 쓴다. Keras `Embedding`은 "단어 번호→학습되는 밀집 벡터" 룩업 테이블이고 **파라미터 = input_dim × output_dim**(맨 앞이 input_dim, bias 없음, input_length는 무관).
> RAG의 `OpenAIEmbeddings`는 **문장을 의미 벡터로** 바꾸며(small 1536·large 3072차원, `dimensions`로 조절), 이 벡터 비교가 RAG 문서 검색의 기반이다.
