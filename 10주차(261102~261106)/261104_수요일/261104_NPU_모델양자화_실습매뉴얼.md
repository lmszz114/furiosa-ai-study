# 261104 NPU 모델 양자화 실습 매뉴얼 — gemma 모델 Q4 양자화

> 큰 LLM을 **양자화(Quantization)** 해 가볍게 만드는 실습. WSL(Ubuntu)에서 llama.cpp로 HuggingFace 모델을 GGUF로 변환한 뒤 4비트로 양자화하고, Ollama에 등록해 실행한다. 파이썬 코드는 없고 터미널 명령 중심이다.

> ⚠️ 명령어 실행 위치: 1번(WSL 생성)만 **Windows PowerShell**에서 하고, 그 뒤로는 전부 **WSL Ubuntu(quant) 안**에서 실행한다.

---

## 0. 먼저 — 양자화가 뭐고 왜 하나

**양자화는 모델 가중치(숫자)의 정밀도를 낮춰 모델을 가볍게 만드는 기술이다.** 예를 들어 16비트(BF16)로 저장된 숫자를 4비트로 줄이면, 모델 용량이 대략 1/4로 줄고 메모리도 덜 쓰며 추론이 빨라진다. 대신 정밀도가 낮아져 **성능(정확도)이 약간 떨어질 수 있다.** "크기·속도를 얻고 품질을 조금 양보하는" 트레이드오프다.

**오늘의 전체 흐름**
```
① WSL(Ubuntu) 환경 생성
② Ollama 설치 → 기본 모델 실행 확인
③ llama.cpp 내려받아 빌드(컴파일)
④ 파이썬 환경(venv) + 변환용 라이브러리 설치
⑤ HuggingFace 모델 → GGUF(BF16)로 변환
⑥ BF16 → Q4_K_M 로 양자화   ← 핵심
⑦ 양자화 모델을 Ollama에 등록하고 실행
```
- **GGUF**: llama.cpp가 쓰는 모델 파일 포맷.
- **BF16**: 16비트 부동소수점(원본에 가까운 정밀도).
- **Q4_K_M**: 4비트 양자화 방식의 하나(K-quant, medium). 용량을 크게 줄인다.

---

## 1. WSL Ubuntu 환경 생성 (PowerShell)

양자화 작업용 리눅스 환경을 WSL로 새로 만든다.

```powershell
wsl --install -d Ubuntu-24.04 --name quant
```
- `-d Ubuntu-24.04`: 설치할 배포판, `--name quant`: 이 배포판에 붙일 이름.
- 최초 실행 시 **Linux 사용자 이름**을 물으면 `quant01` 입력, **비밀번호**는 본인이 정한다(화면에 안 보임). ⚠️ 비밀번호는 문서에 적지 말 것.
- 접속: `wsl -d quant` (또는 설치 직후 자동 진입)

---

## 2. Ollama 설치 (quant01 접속 후)

**Ollama는 로컬에서 LLM을 받아 실행하는 도구**다. 양자화한 모델을 돌려보는 데 쓴다.

```bash
sudo apt update                                   # 패키지 목록 갱신
curl -fsSL https://ollama.com/install.sh | sh     # Ollama 설치 스크립트 내려받아 실행
```

- `curl -fsSL <URL> | sh`: 설치 스크립트를 받아 바로 셸(`sh`)로 실행한다는 뜻. `-fsSL`은 조용히·리다이렉트 따라가며 받는 옵션.

### ⚠️ zstd 에러가 나면

설치 중 아래 에러가 날 수 있다.
```
ERROR: This version requires zstd for extraction. Please install zstd and try again
```
- **원인**: 설치 파일 압축을 푸는 데 필요한 `zstd`(압축 도구)가 없어서다.
- **해결**: zstd를 설치하고 Ollama 설치를 다시 시도한다.
```bash
sudo apt-get install zstd                         # 압축 도구 설치
curl -fsSL https://ollama.com/install.sh | sh     # Ollama 설치 재시도
```

## 3. Ollama 서비스 시작 & 기본 모델 실행 확인

```bash
sudo systemctl status ollama     # Ollama 서비스 상태 확인
sudo systemctl start ollama      # 서비스 시작 (아무 메시지 없이 끝나면 정상)
ollama run gemma4:e2b            # 기본 gemma 모델을 받아 실행 (동작 확인용)
```

- **`systemctl`** 은 리눅스에서 백그라운드 서비스(데몬)를 다루는 명령이다. `status`로 상태 보고, `start`로 켠다. Ollama가 서비스로 떠 있어야 모델을 돌릴 수 있다.
- `ollama run <모델>`: 그 모델을 (없으면 받아서) 실행한다. 여기선 양자화 전에 "Ollama가 제대로 도는지" 확인하는 용도다.

---

## 4. llama.cpp 준비 — 내려받아 빌드(컴파일)

**llama.cpp는 LLM을 C++로 돌리고 변환·양자화하는 도구**다. 양자화에 쓸 `llama-quantize`와 변환 스크립트가 여기 들어 있다.

```bash
# 빌드에 필요한 도구 설치 (C++ 컴파일러·cmake·pip)
sudo apt install -y cmake build-essential python3-pip

# 작업 폴더 만들고 이동
mkdir -p ~/gemma4-quant
cd ~/gemma4-quant

# llama.cpp 소스 내려받기
git clone https://github.com/ggml-org/llama.cpp.git
cd llama.cpp

# 빌드(컴파일)
cmake -B build -DCMAKE_BUILD_TYPE=Release    # build 폴더에 빌드 설정 생성 (Release=최적화)
cmake --build build --config Release -j 8    # 실제 빌드, -j 8 = 8개 작업 동시에(빠르게)

# 양자화 실행파일이 잘 만들어졌는지 확인
./build/bin/llama-quantize --help
```

- **`git clone`**: 깃허브에서 소스 코드를 통째로 복제한다.
- **`cmake`**: C++ 프로젝트를 빌드하는 도구. `-B build`로 빌드 폴더를 만들고, `--build`로 컴파일한다. `-j 8`은 CPU를 8갈래로 써서 빌드를 빠르게.
- **`build-essential`**: gcc 등 C++ 빌드에 필요한 기본 도구 묶음.
- 빌드가 끝나면 `./build/bin/llama-quantize`(양자화 실행파일)가 생긴다. `--help`로 동작 확인.

## 5. 파이썬 환경 구성 — 변환용 라이브러리 설치

HuggingFace 모델을 GGUF로 변환하는 스크립트(`convert_hf_to_gguf.py`)는 **torch 등 파이썬 라이브러리**가 필요하다. 그냥 실행하면 `ModuleNotFoundError: torch` 같은 에러가 난다. 그래서 **가상환경(venv)을 만들고 필요한 라이브러리를 설치**한다.

```bash
# (llama.cpp 디렉토리에서)
sudo apt install -y python3-venv                        # 가상환경 도구 설치

python3 -m venv ~/gemma4-quant/.venv                    # .venv 라는 가상환경 생성
source ~/gemma4-quant/.venv/bin/activate                # 가상환경 활성화
python -m pip install --upgrade pip                     # pip 최신화

# llama.cpp가 지정한 변환용 라이브러리 일괄 설치
python -m pip install -r requirements/requirements-convert_hf_to_gguf.txt

python -c "import torch; print(torch.__version__)"      # torch 버전 뜨면 정상

# 변환에 필요한 추가 라이브러리
python -m pip install --upgrade transformers tokenizer sentencepiece

python -m pip check     # "No broken requirements found" 뜨면 의존성 이상 없음
```

- **venv(가상환경)**: 이 작업 전용으로 파이썬 라이브러리를 격리 설치하는 공간(어제 conda 가상환경과 같은 개념, 도구만 다름). `activate`로 켜면 그 안에 설치된다.
- **`pip install -r <requirements.txt>`**: 파일에 적힌 라이브러리들을 한 번에 설치한다. llama.cpp가 변환에 필요한 목록을 제공한다.
- **`transformers`·`sentencepiece`**: HuggingFace 모델·토크나이저를 다루는 데 필요한 라이브러리.
- **`pip check`**: 설치된 라이브러리들끼리 버전 충돌이 없는지 점검.

## 6. HuggingFace 모델 → GGUF(BF16) 변환

파이썬 환경이 갖춰졌으면, HF 모델을 llama.cpp가 쓰는 GGUF 포맷(BF16)으로 변환한다. (아래 4줄은 한 명령이다 — `\`는 "다음 줄에 이어짐" 표시)

```bash
python3 convert_hf_to_gguf.py \
  --outfile ../gemma4-e2b-bf16.gguf \
  --outtype bf16 \
  --remote google/gemma-4-E2B-it
```

- **`convert_hf_to_gguf.py`**: HuggingFace 모델을 GGUF로 변환하는 스크립트.
- `--outfile`: 만들 결과 파일 경로/이름, `--outtype bf16`: BF16 정밀도로 저장, `--remote <HF모델>`: HuggingFace에서 받아올 모델.
- **줄 끝 `\`** 는 긴 명령을 여러 줄로 나눠 쓴 것으로, 한 번에 실행된다.
- ※ 실습에선 이 변환에서 오류가 나, **이미 변환을 끝낸 사람의 결과 파일(gguf)을 외장하드로 받아 해결**했다. (모델·네트워크 사정에 따라 변환이 실패할 수 있어, 완성된 BF16 gguf를 공유받아 이어서 진행.)

---

## 7. BF16 → Q4_K_M 양자화 (핵심)

변환된 BF16 gguf를 4비트(Q4_K_M)로 양자화한다. llama.cpp 디렉토리에서 실행한다.

```bash
./build/bin/llama-quantize \
../gemma4-e2b-bf16.gguf \
../gemma4-e2b-Q4_K_M.gguf \
Q4_K_M
```

- **`llama-quantize <입력gguf> <출력gguf> <방식>`**: 입력(BF16)을 지정한 방식(`Q4_K_M`, 4비트)으로 양자화해 출력 파일을 만든다.
- 이 단계가 오늘의 핵심이다. 16비트 → 4비트로 줄여 **용량이 대폭 작아진** gguf가 생긴다.

```bash
cd ..            # gemma4-quant 디렉토리로
ls -lp           # 양자화된 파일(gemma4-e2b-Q4_K_M.gguf)이 생겼는지 확인
```
- `ls -lp`: 파일을 상세히(`-l`), 폴더엔 `/`를 붙여(`-p`) 보여준다. 결과 파일이 만들어졌는지 확인.

## 8. Ollama에 등록하고 실행

양자화한 gguf를 Ollama가 쓸 수 있게 **Modelfile**로 등록한다.

```bash
ollama list                                            # 현재 등록된 모델 목록 (gemma4:e2b 확인)

echo "FROM ./gemma4-e2b-Q4_K_M.gguf" > Modelfile       # Modelfile 생성
ls -l                                                   # Modelfile 생성 확인

ollama create gemma4-e2b-myq4 -f Modelfile             # 내 양자화 모델을 Ollama에 등록
ollama run gemma4-e2b-myq4                              # 양자화 모델 실행
```

- **`Modelfile`**: Ollama에 커스텀 모델을 등록하기 위한 설정 파일. `FROM ./<gguf>` 한 줄로 "이 gguf 파일을 모델로 쓴다"고 지정한다. `echo "..." > Modelfile`은 그 내용을 담은 파일을 만드는 명령.
- **`ollama create <이름> -f Modelfile`**: Modelfile을 읽어 그 gguf를 `<이름>`(여기선 `gemma4-e2b-myq4`)으로 Ollama에 등록한다.
- **`ollama run <이름>`**: 등록한 양자화 모델을 실행한다. → 직접 양자화한 경량 모델이 도는 것을 확인.

## 트러블슈팅 요약

| 증상 | 원인 | 해결 |
|---|---|---|
| Ollama 설치 중 `requires zstd` 에러 | 압축 해제용 zstd 없음 | `sudo apt-get install zstd` 후 설치 재시도 |
| `convert_hf_to_gguf.py` 실행 시 `ModuleNotFoundError: torch` | 변환용 파이썬 라이브러리 미설치 | venv 만들고 `requirements-convert_hf_to_gguf.txt` + transformers 등 설치 |
| 변환(convert) 자체가 오류 | 모델/네트워크 등 환경 문제 | 완성된 BF16 gguf를 외장하드로 공유받아 양자화부터 진행 |
| `pip check` 결과 확인 | 라이브러리 버전 충돌 점검 | `No broken requirements found` 나오면 정상 |

## 한 줄 요약

> **양자화**는 모델 가중치의 정밀도를 낮춰(16비트→4비트) 용량·메모리를 줄이고 속도를 올리는 기술이다(품질은 약간 손실). 오늘은 WSL(Ubuntu)에서 **Ollama**(로컬 LLM 실행)와 **llama.cpp**(변환·양자화 도구)를 설치하고, HuggingFace의 gemma 모델을 **`convert_hf_to_gguf.py`로 GGUF(BF16) 변환 → `llama-quantize`로 Q4_K_M(4비트) 양자화** 한 뒤, **Modelfile**로 Ollama에 등록(`ollama create`)해 실행했다. 과정에서 zstd 미설치, torch 등 변환 라이브러리 미설치는 각각 `apt-get install zstd`, venv+requirements 설치로 해결한다.
