## A. NPU에 LLM 올려 쓰기

전 주에 끝낸 NPU 서버 접속·콘다 환경 위에서, 실제로 LLM을 NPU(RNGD)에 올려 API로 불러 쓴다. (셸 명령은 전부 SSH로 접속한 **원격 NPU 서버**에서 실행한다.)

### A-1. LLM 서빙 — OpenAI 호환 API

```bash
hf auth login                              # HuggingFace 토큰으로 로그인(모델 받을 권한)
furiosa-llm serve furiosa-ai/Qwen3-8B-FP8  # NPU에 LLM 올려 OpenAI 호환 서버로 띄움
```
```python
from openai import OpenAI
client = OpenAI(base_url="http://127.0.0.1:8000/v1", api_key="EMPTY")  # 내 NPU 서버
model_id = client.models.list().data[0].id
response = client.chat.completions.create(model=model_id, messages=[...])
```

- **`furiosa-llm serve <모델>`**: 지정한 LLM을 NPU에 적재하고 **OpenAI 호환 API 서버**를 띄운다. "OpenAI 호환"이 핵심 — 기존 OpenAI 클라이언트 코드를 **`base_url`만 로컬 NPU 서버(`127.0.0.1:8000`)로 바꿔** 그대로 쓸 수 있다(`api_key="EMPTY"`, 로컬이라 키 불필요).
- **FP8**: 모델 이름 끝의 FP8은 가중치를 8비트로 줄인(양자화한) 경량 버전. 메모리를 덜 쓰고 추론이 빠르다.
- 서빙 옵션: `--devices npu:5`(장치 지정)·`--host 0.0.0.0`(외부 접속 허용)·`--port 8000`. 상태는 `watch -n 1 furiosa-smi status`로 모니터링한다.

### A-2. fxb 컴파일 · 툴 콜링

- **fxb(모델 컴파일)**: GPU와 달리 NPU는 모델을 **하드웨어에 맞게 컴파일**해 둬야 효율적이다. `fxb build <HF모델> <출력이름>`으로 `.fxb`를 만들고(`--dry-run`으로 미리 점검), `furiosa-llm serve <모델> --fxb ./*.fxb`로 **컴파일 단계를 건너뛰고 빠르게 서빙**한다(한 번 빌드해 재사용).
- **툴 콜링(함수 호출)**: NPU 모델에 "필요하면 이 함수들을 써라"고 알려주면, LLM은 **어떤 함수를 어떤 인자로 호출할지만 정하고(`tools`·`tool_choice`→`tool_calls`), 실제 실행은 코드가** 한다. (OpenAI SDK의 "날것" 버전 — 함수 스펙을 JSON으로 직접 적음. LangGraph의 ToolNode가 이걸 감싼 것.)

### A-3. 모델 양자화

- **양자화(quantization)**: 모델 가중치의 정밀도를 낮춰(예: FP16→FP8/INT) **메모리와 연산량을 줄이는** 최적화. NPU에서 모델을 양자화해 서빙하는 과정을 파워셸 명령 위주로 실습했다. (상세 절차는 `261104_NPU_모델양자화_실습매뉴얼.md` 참고)

### A-4. LangChain 연결 · 스트리밍 · 모듈화

```python
from langchain_openai import ChatOpenAI
llm = ChatOpenAI(base_url="http://127.0.0.1:8000/v1", api_key="EMPTY")
response = llm.invoke("질문")                      # 한 줄로 추론
for chunk in llm.stream("질문"):                   # 스트리밍 (조각씩 실시간)
    print(chunk.content, end="", flush=True)
```

- **LangChain `ChatOpenAI`**: OpenAI SDK 대신 LangChain으로도 NPU 서버에 붙을 수 있다(`base_url`만 로컬). `llm.invoke`/`llm.stream` 한 줄로 간결하고, 이후 체인·RAG·에이전트에 바로 연결하기 좋다.
- **스트리밍**: 답을 다 기다리지 않고 **조각(chunk)씩 실시간 출력**(`end=""`·`flush=True`가 즉시 출력의 핵심) → 체감 반응 속도↑.
- **처리량 TPS** = 출력 토큰 ÷ 시간(여기선 약 144 tokens/s). 생성 파라미터: `max_tokens`·`temperature`(창의성)·`top_p`(샘플링 범위).
- **모듈화**: 반복되는 `ChatOpenAI(...)` 설정을 `get_llm()` 함수로 빼 별도 파일(모듈)로 만들고 `from a_kingkeras import get_llm`으로 재사용한다.

## B. 파이썬 모듈과 패키지

**모듈 = 함수·변수를 담은 `.py` 파일**, **패키지 = 모듈들을 담은 폴더**. `import`로 가져와 재사용한다. (A-4의 모듈화에서 자연스럽게 이어짐)

```python
import 모듈 as 별칭        # 별칭.함수()
from 모듈 import 함수       # 함수() 바로
import 패키지.모듈          # 폴더.파일
from 패키지 import 모듈     # 폴더에서 모듈 가져오기

# ★ 핵심 관용구
if __name__ == '__main__':   # 이 파일을 '직접 실행'할 때만 아래가 돈다
    drive()                  # import될 때는 안 돈다
```

- **`__name__`**: 파이썬이 각 파일에 자동으로 넣는 "이 파일 이름" 변수. **직접 실행하면 `'__main__'`**, 다른 파일에서 **import되면 그 모듈명**이 된다.
- **`if __name__=='__main__':`**: "직접 실행할 때만 돌려라"는 뜻. 파일 끝의 함수 호출이 **import만 해도 실행되는 문제**를 막는 핵심 관용구다(모듈을 "가져다 쓰는 용도"와 "직접 돌리는 용도"를 분리). 거의 모든 실무 코드에 들어간다.
- 각 모듈은 **독립된 이름 공간(스코프)** 을 가져, 서로 다른 파일의 같은 이름 변수(`x`)는 별개다.

## C. 머신러닝 — 교차검증과 하이퍼파라미터 튜닝

### C-1. K-Fold 교차검증

```python
from sklearn.model_selection import KFold, StratifiedKFold, cross_val_score, cross_val_predict
kfold = KFold(n_splits=5, shuffle=True, random_state=333)
scores = cross_val_score(model, x, y, cv=kfold)   # K번 학습·평가를 자동으로
```

- **K-Fold**: 데이터를 K조각으로 나눠 **각 조각을 번갈아 테스트로 쓰고 나머지로 학습**하기를 K번 반복해 평균 낸다. 한 번만 나누는 `train_test_split`보다 **안정적**이다. `cross_val_score`에 전체 `x, y`를 넘기면 내부에서 알아서 나눠 돌린다(train_test_split·fit을 따로 안 씀).
- **올바른 사용**: 전체로 교차검증하기보다, **train/test를 나눈 뒤 train만 교차검증하고 test는 최종 평가에 남겨 두는** 것이 옳다(진짜 일반화 성능 확인). `cross_val_predict`는 예측값을 모아 실제값과 직접 비교(`accuracy_score`/`r2_score`)하게 해준다.
- **StratifiedKFold**: 분류에서 **클래스 비율을 train/test에 똑같이 유지**하는 K-Fold. 회귀는 연속값이라 클래스 개념이 없어 일반 KFold를 쓴다.

### C-2. all_estimators — 모든 모델 한 번에 비교

```python
from sklearn.utils import all_estimators
all = all_estimators(type_filter='classifier')   # 분류 44개 (회귀 55개)
for name, model in all:
    try:
        model().fit(x_train, y_train)
        print(name, model().score(x_test, y_test))
    except: continue   # 안 돌아가는 모델은 건너뜀
```

- 사이킷런의 **모든 분류/회귀 모델을 for문으로 한 번에 돌려** 어떤 게 이 데이터에 잘 맞는지 비교한다. 모델마다 조건이 달라 `try/except`로 오류 모델은 건너뛴다. "어떤 모델을 쓸지" 감이 없을 때 상위 후보를 추리는 **1차 스크리닝**용이다.

### C-3. GridSearchCV — 격자 탐색 자동 튜닝

```python
parameters = [{'n_estimators':[100,500], 'max_depth':[6,10,12], 'learning_rate':[0.1,0.01,0.001]}, ...]
model = GridSearchCV(XGBClassifier(), parameters, cv=kfold, n_jobs=-1, verbose=1)
model.fit(x_train, y_train)
print(model.best_params_, model.best_score_, model.score(x_test, y_test))
```

- **하이퍼파라미터**(학습률·트리 깊이 등 **사람이 학습 전에 정하는 값**)의 최적 조합을 찾는다. 수동 이중 for문(모든 조합 시도)을 **격자 탐색 + 교차검증으로 자동화**한 것이 `GridSearchCV`다.
- **모든 조합을 전부 시도**하되 각 조합을 K-Fold로 평가 → `best_params_`(최적 조합)·`best_score_`(교차검증 평균). 체계적이지만 **조합 수 × fold 수만큼 학습**해 느리다(`n_jobs=-1`로 전체 코어 사용).

### C-4. RandomizedSearchCV · 케라스 튜닝

```python
model = RandomizedSearchCV(XGBClassifier(), parameters, cv=kfold,
                           n_iter=10, random_state=333, refit=True)
```

- **RandomizedSearchCV**: 모든 조합 대신 **무작위로 `n_iter`개만** 교차검증해 훨씬 빠르다(digits 실측: 성능은 Grid와 같고 시간은 절반). **조합이 많을수록 유리**하며, `random_state`로 재현 고정, `refit=True`로 최적 조합을 전체 train에 재학습한다.
- **케라스(딥러닝) 튜닝**: 딥러닝은 파라미터(층·노드·드롭아웃·옵티마이저·배치)가 **매우 많아** Grid가 비현실적이라 Random이 특히 맞는다. 모델을 `build_model()` 함수로 만들고 후보를 딕셔너리로 정의한 뒤, **`KerasRegressor`/`KerasClassifier`로 감싸(wrapper)** 사이킷런의 Search에 넣는다. `fit`에 `epochs`·`callbacks`(EarlyStopping 등)를 그대로 전달한다.

**튜닝 흐름 요약**: 수동 for(m07) → GridSearchCV(전부, m08) → RandomizedSearchCV(무작위 일부, m09) → (다음 주 HalvingGridSearchCV로 완성).

## 한 주 핵심 한 줄

> **NPU LLM 실습**: `furiosa-llm serve`로 NPU에 LLM을 올려 **OpenAI 호환 API**로 띄우면 기존 코드를 `base_url`만 로컬(`127.0.0.1:8000`)로 바꿔 쓸 수 있고, `fxb build`로 **컴파일(.fxb)** 해 두면 빠르게 서빙되며, **툴 콜링**은 LLM이 호출만 정하고 코드가 실행한다. **LangChain `ChatOpenAI`** 로 붙으면 `llm.invoke`/`llm.stream`(스트리밍, `flush=True`)이 간결하고, 설정은 `get_llm()`으로 **모듈화**한다. **파이썬 모듈/패키지**는 `import`로 재사용하되 파일 끝 호출이 import 시에도 실행되므로 **`if __name__=='__main__':`** 으로 막는다. **머신러닝**은 **K-Fold**(train만 교차검증 + test 최종 평가, 분류는 StratifiedKFold)와 **all_estimators**(전 모델 1차 비교)로 평가하고, 하이퍼파라미터는 **GridSearchCV**(전부)→**RandomizedSearchCV**(무작위 일부, 케라스는 `KerasRegressor` wrapper로)로 튜닝한다.
